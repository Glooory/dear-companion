# 互动动作回切转场修复设计

日期：2026-08-10

## 问题

互动动作结束时，`PetShell` 会立即清除动作状态，使外层动画模板恢复为 `still`；`PhotoTransition` 则在收到静态照片后才开始异步预载和遮挡式回切。两条时间线未协调，而且动作动画、照片入场动画都写入同一个 `transform`，导致互动照片切回静态照片时可能出现白色闪烁和缩放跳变。

## 设计

- `PhotoTransition` 继续负责照片预载、遮挡、替换和揭示，旧照片在新照片成功加载前保持可见。
- 静止阶段不再携带照片入场动画类；只有真正进入揭示阶段时才播放入场动画，避免普通渲染和动作类争用 `transform`。
- 照片框的几何位置和尺寸增加短暂、平滑的过渡。素材切换时，人物的归一化高度、偏移和宽度变化由同一照片框连续插值恢复。
- 动作模板在照片回切完成前保持稳定；`PhotoTransition` 在完成揭示后通知 `PetShell`，随后才清除动作状态。没有发生素材切换的纯 CSS 动作仍按原时长结束。
- 遮挡元素降低近白色实心覆盖感，但保留泡泡、云朵和星光三种既有视觉语言。
- 新素材加载失败时继续显示最后一张成功加载的照片，并结束等待，避免动作状态永久滞留。

## 边界与异常

- 连续触发新动作、拖动、窗口隐藏、生活状态变化或系统流程开始时，取消旧计时和旧回切等待；最新状态优先。
- 不改变动作槽、生活状态、图片归一化元数据或 IPC 接口。
- 不增加远程资源、图片处理服务或新的产品设置。
- 尊重 `prefers-reduced-motion` 的现有处理；低动态模式下过渡时间由全局样式压缩。

## 验证

- 本次主要修改属于渲染时序和样式，不新增 React/UI 自动化测试。
- 运行 lint、类型检查、生产构建和非视觉 Electron 启动冒烟检查。
- 界面效果由用户手动确认：互动动作结束无白闪，互动照片回到静态照片时缩放和位置平滑，快速连续互动与素材加载失败不会卡住。
