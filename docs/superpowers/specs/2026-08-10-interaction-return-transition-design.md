# 互动动作回切转场修复设计

日期：2026-08-10

2026-09-10 修订：照片切换统一采用约 400 毫秒的交叉淡化，不再使用云朵、泡泡、星光或其他遮挡元素。

## 问题

互动动作结束时，`PetShell` 会立即清除动作状态，使外层动画模板恢复为 `still`；`PhotoTransition` 则在收到静态照片后才开始异步预载和交叉淡化回切。两条时间线未协调，可能导致互动照片切回静态照片时出现闪烁或状态提前结束。

## 设计

- `PhotoTransition` 负责照片预载和交叉淡化，旧照片在新照片成功加载前保持可见。
- 新照片加载成功后，同时渲染新旧照片：旧照片淡出，新照片淡入；约 400 毫秒后移除旧照片。
- 转场只改变照片透明度，不加入云朵、泡泡、星光或其他遮挡元素，也不额外改变人物缩放和位置。
- 动作模板在照片回切完成前保持稳定；`PhotoTransition` 在交叉淡化完成后通知 `PetShell`，随后才清除动作状态。没有发生照片切换的纯 CSS 动作仍按原时长结束。
- 新素材加载失败时继续显示最后一张成功加载的照片，并结束等待，避免动作状态永久滞留。

## 边界与异常

- 连续触发新动作、拖动、窗口隐藏、生活状态变化或系统流程开始时，取消旧计时和旧回切等待；最新状态优先。
- 不改变动作槽、生活状态、图片归一化元数据或 IPC 接口。
- 不增加远程资源、图片处理服务或新的产品设置。
- 尊重 `prefers-reduced-motion` 的现有处理；低动态模式下交叉淡化时间由全局样式压缩。

## 验证

- 本次主要修改属于渲染时序和样式，不新增 React/UI 自动化测试。
- 运行 lint、类型检查、生产构建和非视觉 Electron 启动冒烟检查。
- 界面效果由用户手动确认：互动动作结束无白闪或空白帧，互动照片通过交叉淡化回到静态照片，快速连续互动与素材加载失败不会卡住。
