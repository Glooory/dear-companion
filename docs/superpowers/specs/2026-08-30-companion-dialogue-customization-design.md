# Dear Companion 对白与称呼自定义设计

日期：2026-08-30

2026-09-04 修订：伙伴详情和对白编辑层级已改为二级页签、五个场景页签和卡片内直接编辑；按句配音、录音、音频导入、本地文件生命周期和可访问性详见 `2026-09-04-companion-dialogue-voice-design.md`。本文中的嵌套页面示意被新设计取代，对白分类、编辑、称呼、校验和选择规则继续有效。

## 1. 目标与范围

本设计让用户看见并调整伙伴在不同生活场景与互动时机使用的对白，并为每个伙伴分别设置“对你的称呼”。用户可以修改或停用内置对白、添加自己的对白，并在对白中插入称呼占位符。实际显示时继续使用现有随机选择、分类冷却和短期防重复机制。

本功能保持完全离线。称呼和对白只保存在当前伙伴的本地配置中，不上传、不记录遥测，也不引入账号、云同步或内容审核服务。

本次不包含：

- 用户创建新的生活场景、触发原因、冷却时间或气泡时长。
- 修改休息提醒、倒计时、休息完成、错误消息等系统必要文案；提醒计划原有的可编辑提示文案不受影响。
- 在右键菜单中配置快捷互动。
- 将对白、可选照片和可选内置动作组合为自定义快捷互动。
- 自由动画参数、时间轴、关键帧或用户自定义动作模板。

“快捷互动”是后续独立功能方向。它可能组合特定对白、可选照片与可选内置动作，但需要另行确定状态优先级、素材回退、右键菜单组织和系统流程边界。本设计只为每条对白提供稳定 ID，不预存未使用的快捷互动字段。

## 2. 产品原则

- 对白配置归属于单个伙伴。切换伙伴后，称呼和对白随伙伴切换。
- 用户编辑的是某个互动时机最终使用的一张对白清单，不维护“内置池”和“用户池”两套使用模式。
- 场景与互动时机由程序固定，界面使用生活化名称，不暴露内部状态名和触发规则。
- 内置对白对用户透明，可以修改、停用和恢复；用户对白可以添加、修改、停用和删除。
- “自动使用”只表示该对白是否进入对应时机的随机池，不表示对白是否存在。这个命名为后续快捷互动保留清晰边界。
- 产品提供的内置对白继续遵守现有文案原则。用户自己编写的私有内容不受产品语调约束，程序不做敏感词过滤或自动改写。

## 3. 信息架构

### 3.1 伙伴详情入口

“对白与称呼”位于“我的伙伴”的当前伙伴详情中，不新增顶层设置分类。伙伴详情显示摘要卡：

```text
对白与称呼
豆包称呼你为“小葡萄” · 自定义 8 句

[编辑对白]
```

没有称呼和用户对白、且内置对白未被调整时，摘要改为“当前使用内置对白”。

### 3.2 对白首页

进入独立的嵌套编辑页后，保留当前伙伴上下文：

```text
‹ 返回伙伴设置                  豆包的对白

对你的称呼
[ 小葡萄                              ]
在对白中插入“称呼”时使用；可以留空。

平时陪伴     5 个时机 · 自定义 3 句    >
有点困了     3 个时机 · 使用内置对白  >
睡觉         5 个时机 · 自定义 4 句    >
专注陪伴     3 个时机 · 自定义 1 句    >
其他互动     1 个时机 · 使用内置对白  >

休息提醒、倒计时和状态提示由程序管理。
```

困倦或睡觉场景尚未启用时仍可编辑，对应页面显示“这个场景尚未启用，设置会保留”。

### 3.3 场景与互动时机

用户可编辑以下固定分组：

- **平时陪伴**：被点一下、活泼时被点、被摸摸头、主动开口、回到日常。
- **有点困了**：刚开始犯困、被点一下、被摸摸头。
- **睡觉**：刚睡着、轻声叫它、快醒了、完全醒来、睡着时摸摸。
- **专注陪伴**：刚进入专注、被点一下、被摸摸头。
- **其他互动**：拖动太快。

生活场景与互动时机在共享契约中使用固定、稳定的内部 ID。设置界面不允许创建、删除或重命名这些分类。

### 3.4 具体时机编辑

一个互动时机显示一张统一对白清单：

```text
轻声叫它

[自动使用：开]  唔……                         内置
[自动使用：开]  [称呼]，我听见了……          内置 · 已修改
[自动使用：关]  还没醒呢……                  内置
[自动使用：开]  再让我睡一会儿。             我的  [删除]

[＋ 添加一句]  [插入称呼]

[恢复内置对白]
```

- 内置对白不能永久逐条删除，只能修改或停用。
- 修改过的内置对白显示“已修改”，并提供“恢复原句”。恢复原句只恢复文字，保留当前自动使用状态。
- 用户对白可以修改、停用和删除。
- `恢复内置对白`恢复该时机所有内置原句并重新开启自动使用，用户对白及其状态、伙伴称呼均保持不变。
- 恢复前说明“内置对白将恢复原文并重新启用，你添加的对白不会改变”。
- 所有对白都停用是合法状态；伙伴在该时机只播放动作，不显示非必要气泡。

### 3.5 称呼与预览

- 用户通过“插入称呼”在当前光标位置插入可见的 `[称呼]`，不需要记忆模板语法。
- 预览显示完成称呼替换后的最终文字。
- 称呼为空时，包含 `[称呼]` 的对白暂不参与预览和实际随机选择，不把占位符替换为空字符串。
- 对白首页在“日常对话气泡”总开关关闭时说明“日常对话气泡已关闭；设置会保留，重新开启后生效”，但不阻止编辑。

### 3.6 保存

对白页使用当前伙伴的同一份设置草稿，并提供与伙伴详情一致的“保存设置”。返回上一级不会丢弃草稿。保存仍通过窄、类型安全的宠物更新接口一次原子写入当前伙伴配置；失败时保留草稿并说明原设置没有改变。

## 4. 数据模型

每条内置对白和用户对白都有稳定 ID。内置对白目录包含分类、行 ID 和产品默认文字；用户配置只保存相对于内置目录发生的变化和用户新增内容，不复制整套默认对白。

```ts
interface PetDialogueSettings {
  address: string;
  categories: Partial<Record<DialogueCategory, DialogueCategorySettings>>;
}

interface DialogueCategorySettings {
  builtInOverrides: readonly BuiltInDialogueOverride[];
  customLines: readonly CustomDialogueLine[];
}

interface BuiltInDialogueOverride {
  lineId: string;
  automaticEnabled?: boolean;
  text?: string;
}

interface CustomDialogueLine {
  id: string;
  automaticEnabled: boolean;
  text: string;
}
```

- 未修改的内置对白没有 override。
- 修改文字或停用自动使用时才保存对应 override。
- “恢复原句”删除该行的文字 override；“恢复内置对白”删除该时机的全部内置 override。
- 用户对白 ID 在伙伴范围内唯一，未来其他伙伴功能可以通过稳定引用使用，不依赖文字匹配。
- 已不存在的内置行 ID 不参与运行时选择；配置仍受数量和标识符格式限制。

应用仍在开发阶段，本次持久化结构变更不提供旧开发配置迁移，也不把已有本地开发数据保留列为验收要求。配置使用新的明确 schema 版本；不符合新结构的开发数据可以重建。

## 5. 有效对白池

运行时按以下顺序生成某个互动时机的有效对白池：

1. 读取该时机的当前内置对白目录。
2. 应用用户保存的内置文字修改和自动使用状态。
3. 加入自动使用已开启的用户对白。
4. 使用当前伙伴的称呼替换 `[称呼]`。
5. 称呼为空时跳过包含称呼占位符的条目。
6. 去除空白、无效和最终文字完全重复的条目。
7. 将结果交给现有 `DialogueSelector` 执行分类冷却、随机选择和最近两句防重复。

防重复比较完成称呼替换后的最终文字。有效池为空时安全返回，不影响当前动作、生活状态或后续调度。

“日常对话气泡”总开关关闭时，所有本设计中的非必要对白暂停显示，但配置保持不变。休息邀请、倒计时、休息哭闹、休息完成、错误消息和其他必要系统气泡不使用用户对白池，也不受该开关影响。

内置对白目录发生变化时：

- 新内置对白默认自动使用。
- 已修改的内置对白保留用户文字。
- 已停用的内置对白保持停用。
- 已移除的内置对白不再参与运行。
- 恢复操作使用当前程序版本的内置原文。

## 6. 输入校验

- 对你的称呼可以留空，最多 12 个 Unicode 可见字符。
- 单句对白建议 4–12 个字，最多 30 个 Unicode 可见字符。
- 每个互动时机最多 20 条用户对白。
- 对白必须是单行非空文字，不接受换行或不可见控制字符。
- 保存时去除首尾空白，不擅自修改中间标点和空格。
- 同一互动时机的完全重复模板不重复保存，称呼替换后的重复文字在运行时再次去重。
- 第一版只识别 `[称呼]`，不提供日期、时间、伙伴名称或任意变量语法。
- 用户可以输入 emoji；产品内置对白不使用 emoji 作为结构图标或依赖 emoji 塑造性格。

字符数量按 Unicode 用户可见字符计算，避免把 emoji 或组合字符错误计算成多个字符。渲染器提供即时反馈，主进程对完整 payload 再次执行严格校验。

## 7. 错误与可访问性

- 普通字段在失焦时显示具体的行内错误。
- 保存存在错误时，通过全局 Toast 提示存在未填写或不合规项，并将焦点直接移至首个错误字段；不展示顶部冗余的错误摘要横幅。输入框继续保留具体的行内错误。
- 错误不能只用颜色表达，输入与错误通过无障碍属性关联。
- 停用控件使用原生语义并公布当前状态；删除和恢复按钮有可理解的可访问名称。
- 保存失败保留全部草稿，持久化层继续保持原子写入和上一份有效配置保护。
- 配置解析或对白解析失败时不显示损坏文字，安全回退到可用的内置对白或静默动作。

## 8. 测试与验收

自动化测试只覆盖必要核心逻辑和可复用共享方法：

- 对白分类、稳定 ID、配置数量和输入长度的严格解析。
- 内置对白修改、停用、单句恢复和分类恢复后的有效池。
- 恢复内置对白不改变用户对白和称呼。
- 用户对白添加、修改、停用和删除。
- 称呼替换、称呼为空时跳过和最终文字去重。
- 有效池为空时安全返回。
- 总气泡开关与必要系统气泡的边界。
- 现有分类冷却和短期防重复。

不添加 UI 单元测试、React 组件测试、快照测试、浏览器测试或自动化端到端测试。实现完成时执行允许的完整单元测试、lint、类型检查、生产构建和非视觉 Electron 启动冒烟检查。

以下项目等待用户在 Windows 与 macOS 手动验证：

- 对白首页、场景层级和返回导航易于理解。
- 内置与用户对白的来源、修改和自动使用状态清晰。
- 插入称呼、预览、停用、删除和恢复操作符合预期。
- 长度上限内的对白在桌面气泡中可读。
- 键盘焦点顺序、行内错误关联和控件名称可理解。
- 总气泡开关关闭后设置仍保留，重新开启后生效。

## 9. 完成标准

- 每个伙伴分别保存称呼和对白设置，切换伙伴不串用内容。
- 用户可以查看所有可编辑的内置对白，修改或停用单句并恢复内置内容。
- 用户可以按生活场景与互动时机添加、修改、停用和删除自己的对白。
- `[称呼]`在显示前正确替换；称呼为空时不会产生残缺句子。
- 自动对白继续遵守分类冷却、短期防重复和总气泡开关。
- 必要系统气泡不被用户对白设置覆盖或关闭。
- 配置与 IPC payload 经过严格校验，失败不破坏上一份有效设置。
- 本次不实现右键菜单快捷互动，也不引入未使用的快捷互动配置字段。
