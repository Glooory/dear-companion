# 全身人物照片伙伴动效设计

日期：2026-09-10

## 1. 目标

Dear Companion 的伙伴素材是用户准备的透明背景人物全身照，不是带骨骼、局部图层或可生成中间帧的动画角色。本设计重塑伙伴的自动活动与鼠标互动，使静态全身照既保持人物比例和照片质感，又能通过轻度卡通物理呈现自然、鲜明但不过度打扰的陪伴感。

整体方向为“真人照片 × 轻度卡通物理”：约七成自然克制、三成俏皮。大胆感主要来自有节奏的窗口位移、清晰的互动反馈和动作组合，不来自夸张拉伸人体。

本设计细化并修订主规格中的伙伴动作模板、自动活动、悬停、单击、摸头、身体推动、拖动、生气、哭闹和减少动态效果行为。照片用途、生活状态优先级、提醒与休息流程、对白规则和约 400 毫秒的照片交叉淡化保持不变。

## 2. 素材约束与动作原则

### 2.1 默认素材能力

每张素材默认只能作为一个不可拆分的平面整体进行渲染。程序不得假设能够单独控制头、眼睛、肩膀、手臂、膝盖、衣服或头发。

只有用户提供姿势匹配的另一张完整照片时，才允许通过照片切换表达眨眼、哈欠、挥手、伸懒腰或其他具体身体动作。程序不从单张照片生成局部动作，也不新增骨骼绑定、图像分割、AI 补帧或自动人脸处理。

### 2.2 允许的动作能力

普通动作只使用以下能力：

- 整张照片的小幅二维平移。
- 围绕脚底基线的小角度二维旋转。
- 不超过约 1% 的轻微等比或纵向缩放。
- 在显示器工作区内移动伙伴窗口。
- 切换用户已经提供并完成归一化的完整照片。
- 在人物之外独立渲染爱心、眼泪等少量情绪叠层。

所有整图变换以人物脚底中心为默认原点。普通动作不使用 `rotateX`、`rotateY` 等卡片式三维翻转，不以明显非等比缩放模拟肢体动作，不让脚底在呼吸和重心动作中无故滑动。

### 2.3 位移缩放

动作位移随伙伴显示高度调整，并设置最小与最大 DIP 边界，避免 80 px 的小伙伴动作过大，也避免 260 px 的大伙伴动作过弱。旋转角度保持固定上限，不随照片尺寸无限增大。

同一时刻只播放一个普通身体动作。爱心或眼泪可以与对应身体动作同时出现，但不能叠加第二个显眼身体动作。每个动作必须以中性姿势结束，取消动作时也必须清理临时变换。

## 3. 动效分层

伙伴渲染使用职责分离的变换层，避免悬停、拖动、身体动作和照片转场争用同一个 `transform`：

```text
位置层：伙伴窗口在桌面上的真实位置
└─ 注意力层：悬停方向与拖动方向倾斜
   ├─ 动作层：呼吸、弹跳、摸头、生气等短动作
   │  └─ 照片层：人物照片、归一化几何与交叉淡化
   └─ 叠层：爱心、眼泪等独立反馈
```

- 位置层继续通过受限的主进程窗口移动接口工作。
- 注意力层只保存当前方向变量，不负责动作计时。
- 动作层一次只接受一个动作定义，结束或被高优先级流程取消后回到中性值。
- 照片层只负责图片加载、几何位置和透明度交叉淡化，不参与身体形变。
- 叠层的位置由当前照片几何或头部热区计算，不使用固定窗口百分比猜测人物头部位置。

## 4. 统一动作定义

建立一个小型、显式的动作定义表，作为 CSS 动画和业务计时的唯一时长来源。每个定义至少包含：

- 稳定的动作名称。
- 标准持续时间。
- 允许使用的生活状态。
- 是否移动伙伴窗口。
- 可选的方向参数。
- `prefers-reduced-motion` 下的替代动作。

动作状态的占用时间必须与实际视觉动画一致，不再在调用位置和 CSS 中分别维护互相冲突的毫秒数。

时长分组如下：

- 即时反馈：100–180 毫秒。
- 单击回应：420–720 毫秒。
- 摸头回应：800–1000 毫秒。
- 拖动回稳：220–320 毫秒。
- 生气反馈：900–1200 毫秒。
- 生命底噪：1400–2000 毫秒。
- 自主移动：600–900 毫秒。
- 照片交叉淡化：约 400 毫秒。

## 5. 基础动作模板

### 5.1 轻呼吸

- 标准持续时间约 1800 毫秒。
- 纵向最大放大约 0.7%，横向不变。
- 以脚底为原点，透明度保持不变。
- 只作为间歇短动作，不持续循环播放。

### 5.2 换重心

- 向随机一侧旋转约 0.7°并水平移动约 1 DIP。
- 在偏移位置停顿约 180 毫秒后缓慢回正。
- 相邻两次优先使用不同方向。

### 5.3 轻轻踮起

- 整体上移约 2 DIP，停留约 120 毫秒后回落。
- 不缩放人物。
- 仅用于自然和爱玩节奏，不用于睡觉、困倦、专注或系统流程。

### 5.4 探身观察

- 向目标方向平移约 2 DIP，并围绕脚底旋转约 1.5°。
- 停留约 250 毫秒后回正。
- 方向随机或来自当前光标方向；相邻两次不固定在同一侧。

### 5.5 轻抬回应

- 整体快速上移约 3 DIP，再平稳回落。
- 不使用横向压扁或纵向拉长。
- 作为日常点击的基础反馈。

### 5.6 玩心小跳

- 单跳上移约 5–7 DIP；双跳依次约 6 DIP 和 4 DIP。
- 第二跳节奏略快，最终完整回到脚底基线。
- 人物本体不做明显挤压；如需要离地感，由独立地面阴影承担，且阴影只能作为可选的低对比叠层。

### 5.7 困倦下沉

- 缓慢向随机一侧旋转约 1.6°并下降约 3 DIP。
- 停顿约 100 毫秒后较快回正。
- 不超过看起来像站立失衡而非整个人倒下的幅度。

### 5.8 抚摸靠近

- 根据摸头完成点向左或向右倾斜，最大约 1.2°。
- 下沉不超过约 2 DIP，可增加最多约 0.4% 的等比缩放。
- 睡觉时改为一次加深呼吸；困倦时改为缓慢下沉；专注时只保留克制侧倾。

### 5.9 放稳

- 普通拖动释放后下沉约 2 DIP，并在 220–320 毫秒内回到中性姿势。
- 不压扁人物，不模拟并不存在的落地冲击。

### 5.10 生气摇晃

- 快速拖动释放后先静止约 70 毫秒，表达受惊。
- 随后水平抖动三轮，每侧约 4 DIP，旋转不超过约 0.8°。
- 动作结束前停顿约 120 毫秒，再稳定回正。

### 5.11 哭闹微颤

- 哭闹不再复用生气摇晃。
- 人物下沉约 2 DIP，并进行低幅、不连续的水平微颤。
- 眼泪从头部热区附近以错峰方式出现；哭闹结束时人物回到中性姿势。

## 6. 自动活动

保留现有生命底噪、自主小动作和性格事件三层调度，以及安静、自然、爱玩三档既有时间范围。悬停和短交互继续只暂缓已经到期的动作，不重新抽取整段等待时间。

### 6.1 生命底噪动作池

- `daily-calm`：轻呼吸、换重心。
- `daily-playful`：轻呼吸、换重心、低概率轻轻踮起。
- `drowsy`：轻呼吸、困倦下沉。
- `sleeping`：只使用更低幅的轻呼吸；有姿势匹配的闭眼照片时才允许照片式眨眼。
- `working`：轻呼吸、极低幅换重心，不主动说话。

### 6.2 自主小动作

自主小动作只在日常安静和日常活泼状态可用：

- 探身观察：不移动窗口。
- 两步靠近：先向移动方向倾斜约 1.2°，再分两步移动窗口，每步约 6–9 DIP，并同步产生 1–2 DIP 的轻微起伏。
- 两步靠近完成后停顿约 220 毫秒，保留新的窗口位置，不强制返回原点。
- 所有窗口移动继续限制在当前显示器工作区内。

减少动态效果开启时禁用自主窗口移动。

### 6.3 性格事件

- 安静档：探身观察、姿态整理，自动对白概率最低。
- 自然档：探身观察、轻轻踮起、低概率玩心小跳或切换另一张日常照片。
- 爱玩档：单跳、双跳、两步靠近或低概率切换另一张日常照片。
- 自动对白只伴随少部分性格事件，动作本身承担主要表达。

动作选择使用小型洗牌袋或等价的短期记忆，避免同一动作或同一方向连续重复。重置伙伴、生活状态或节奏档位时可以清空对应记忆。

## 7. 鼠标互动

### 7.1 悬停跟随

悬停使用二维靠近感，不使用 `rotateX` 或 `rotateY`：

- 以当前照片可见人物区域计算光标方向，而不是使用整个透明窗口。
- 左右旋转不超过约 1.6°，水平位移不超过约 2 DIP，垂直位移不超过约 1 DIP。
- 进入响应约 110 毫秒。
- 光标离开人物后保留最后方向约 80 毫秒，再用约 220 毫秒回正。
- 摸头候选、拖动、普通动作或系统流程开始时释放悬停姿态。

### 7.2 单击

普通单击根据当前生活状态选择动作，不再从全局统一动作池平均随机：

- `daily-calm`：以轻抬回应为主，少量慢侧倾或低幅全身前倾。
- `daily-playful`：单跳、双跳或不超过约 2° 的左右扭身。
- `drowsy`：先快速上移约 2 DIP，再缓慢下沉恢复。
- `working`：下沉约 1 DIP 后回稳，不弹跳或扭动。
- `sleeping`：继续使用三阶段叫醒流程。

睡觉叫醒流程为：第一次轻微晃动睡眠照片；第二次在可用时切到困倦照片并短暂下沉；第三次切回日常照片、进入最短清醒期并播放清醒回稳。

### 7.3 摸头

摸头检测完成事件增加最小必要的方向结果，用于选择人物靠近方向。结果只需要表达向左、向右或无明确水平方向；不向渲染层暴露完整全局轨迹，不持久化，也不写入日志。

- 从人物左侧完成时向左轻靠，从右侧完成时向右轻靠；无明确方向时只下沉。
- 爱心位置依据当前照片的头部热区计算。
- 每次触发显示一颗主爱心；可以低概率显示一颗较小的错峰爱心，但不叠加第二个身体动作。
- 生活状态继续决定睡觉、困倦与专注时的克制回退。

### 7.4 身体推动

保留头部热区之外可见身体区域的水平推动识别：

1. 人物先向受力反方向倾斜约 0.8°。
2. 窗口沿推动方向移动约 6–10 DIP。
3. 移动中同步一次约 1 DIP 的起伏。
4. 人物在约 180 毫秒内站稳。

继续保留动作冷却，并在摸头候选期间禁用身体推动。

### 7.5 拖动与释放

- 拖动期间人物保持刚性，不进行纵横拉伸。
- 根据最近的水平移动方向产生最大约 1.2° 的反向倾斜。
- 窗口始终直接跟随光标，不增加惯性或延迟。
- 普通释放播放“放稳”。
- 快速释放播放“生气摇晃”并显示抗议对白。
- 停止移动约 80 毫秒后，拖动方向倾斜逐渐回正。

## 8. 动作优先级与取消

现有系统流程、生活状态和短动作优先级保持不变。新增约束如下：

- 提醒、休息、哭闹和庆祝可以取消普通悬停、自动动作与鼠标互动动作。
- 拖动可以立即取消悬停、摸头候选和当前普通动作。
- 新的主动点击或摸头可以替换尚未结束的低优先级普通动作，但必须先清理旧动作的计时器和临时 CSS 变量。
- 照片切换期间不启动新的普通身体动作；交叉淡化结束后才恢复调度。
- 页面隐藏、伙伴隐藏或系统休眠时停止视觉动画并清理未完成的窗口位移步骤。

## 9. 减少动态效果

`prefers-reduced-motion: reduce` 使用语义降级，而不是只把 CSS 动画压缩到近零时长：

- 禁止自主窗口移动、弹跳、快速摇晃和持续悬停跟随。
- 保留低幅轻呼吸。
- 单击降级为一次不超过约 0.3% 的等比脉冲或直接的对白反馈。
- 摸头保留静态爱心的短暂淡入淡出，不播放人物侧倾。
- 身体推动不触发自主位移式动画；用户直接拖动仍保持可用。
- 状态照片继续交叉淡化，但使用缩短后的过渡。
- 业务动作占用时间与降级后的视觉时长同步缩短，不允许出现画面已经静止但互动仍被锁住的情况。

## 10. 失败回退与兼容性

- 未识别或不适用于当前状态的动作回退到中性静止，不借用其他生活状态照片。
- 动作所需照片加载失败时保留当前照片，并结束动作等待。
- 头部热区缺失或无效时继续使用内置默认区域；仍无法计算方向时使用无方向摸头反馈。
- 切换减少动态效果、伙伴、节奏档位或页面可见性时，取消不再适用的动作并回到中性值。
- 本次不增加用户可编辑动作参数、动作模板选择、关键帧时间轴或新的素材必填项。
- 本次不增加依赖、网络能力、遥测或对用户照片内容的日志记录。

## 11. 验证

必要核心逻辑和可复用方法的单元测试覆盖：

- 动作定义与标准持续时间。
- 不同生活状态和陪伴档位的动作池。
- 动作与方向的短期防重复。
- 摸头完成方向结果及无方向回退。
- 自主移动步长、净位移和工作区约束。
- 减少动态效果下的动作映射和占用时长。
- 动作取消时的核心状态恢复。

不增加 UI 单元测试、React 组件测试、快照测试、浏览器测试或自动化端到端测试。实现完成后运行允许的完整单元测试、lint、类型检查、生产构建和非视觉 Electron 启动冒烟检查。

以下项目全部等待用户在 Windows 与 macOS 手动验证：

- 全身人物照片在呼吸、倾斜、弹跳和回稳时没有明显人体拉伸或脚底滑动。
- 悬停方向、鼠标离开回正和连续交互衔接自然。
- 摸头方向、爱心位置、身体推动、拖动倾斜和快速拖动生气符合手势预期。
- 三种陪伴档位具有不同性格，但普通桌面工作期间不过度打扰。
- 自主两步靠近不会明显滑行、越出工作区或频繁改变伙伴位置。
- 困倦、睡觉、专注、提醒、休息、哭闹和庆祝不会播放不合时宜的活泼动作。
- 减少动态效果开启后仍有克制反馈，且没有不可见的互动锁定。
- 待机与动作期间的 CPU 和内存符合主规格软预算。
