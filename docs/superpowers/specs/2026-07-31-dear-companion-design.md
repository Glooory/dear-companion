## 1. 产品目标

Dear Companion 是一款面向 Windows 和 macOS 的离线桌面宠物应用。用户导入自己已经抠好、带透明背景的人物照片，将其配置为会卖萌、响应鼠标互动并邀请用户休息的桌面伙伴。

第一版面向家人和少量朋友分发。应用不需要账号、不连接云端，也不上传照片、声音或配置。用户通过安装包使用应用；GitHub Actions 自动构建发布产物。

第一版的核心价值是：只用少量静态人物照片，也能得到自然、轻量、可配置的桌面陪伴体验。

## 2. 第一版范围

### 2.1 包含功能

- 透明、无边框、置顶的桌面宠物窗口。
- 默认人物显示高度约 180 px，可在 80–260 px 范围内缩放。
- 自动保存宠物在桌面上的位置，并确保它始终位于某块可见屏幕内。
- 单击根据当前生活状态触发强互动；睡觉期间连续点击可以逐步叫醒宠物。
- 每张照片默认具有椭圆形头部热区，用户可以调整其位置与大小；鼠标在热区附近往返移动时触发摸头反馈，并允许光标短暂移出宠物窗口再返回。
- 从头部热区开始的轨迹只参与摸头识别，摸头候选期间不触发身体推动；日常状态下，头部热区之外的可见身体区域才响应水平推动。
- 鼠标悬停时，宠物根据照片可见人物区域以二维小位移和脚底轴轻微倾斜靠近光标，不使用卡片式三维翻转。
- 用户可以拖动宠物；拖动过快时宠物会短暂生气抗议。
- 右键菜单和系统托盘提供显示、隐藏、设置和退出等操作。
- 用户导入透明 PNG 或 WebP，程序负责透明边距裁切、视觉高度归一化、脚底基线对齐和预览微调。
- 用户将照片分配给平时陪伴、有点困了、睡觉和陪伴工作等生活用途，并可保留卖萌、生气、哭闹、休息和闭眼等短动作素材。
- 困倦和睡觉可分别启停，没有可用照片时安全跳过；工作照片可选，缺失时使用日常照片。
- 日常陪伴在安静与活泼节奏间自动切换，困倦与睡觉可在非工作、非提醒、非休息时随机出现。
- 日常状态通过适配全身照片的间歇轻呼吸、换重心或轻微踮起维持低打扰的生命感，并在不同陪伴档位下偶尔探身观察、弹跳或分两步改变桌面位置；有姿势匹配的闭眼照片时才使用照片式眨眼。普通悬停或短交互不会反复重置已经等待的自主动作。
- 支持多个用户自建工作时段以及右键手动进入或退出工作模式。
- 所有照片切换统一使用内置短交叉淡化，避免静态照片直接硬切。
- 按生活场景与互动原因分类的气泡对白，带冷却和短期防重复；用户可为每个伙伴分别设置称呼，查看、修改、停用和恢复内置对白，并添加自己的对白。用户可为每句对白录制最长 8 秒的声音或导入不超过 5 MB 的 MP3、WAV、OGG、WebM 或 M4A；对白声音默认关闭。用户仍可整体关闭非必要互动气泡。
- 用户可为每个伙伴选择最多三句非休息系统对白作为“常用对白”，通过伙伴右键菜单手动显示该句当前文字，并在对白声音开启且配音可用时播放已有配音。
- 内置轻呼吸、换重心、踮起、探身、弹跳、抚摸靠近、放稳、生气摇晃、哭闹微颤和照片切换等动作模板；普通动作不明显拉伸或压扁人物身体。
- 支持多个用户自建提醒计划；每条计划可选择固定时间，或在最多三个当天时段内按统一间隔重复；首次安装的提醒列表为空。
- 提醒到点后，宠物通过对话气泡邀请用户立即开始或延后 5、10、15 分钟。
- 休息期间宠物坐下或打盹，气泡上层展示休息文案或督促对白，下层工具栏独立稳定显示剩余倒计时与结束按钮。
- 休息期间检测鼠标移动；超过容差后宠物哭闹（持续移动顺延哭闹对白与表现，手停约 3 秒后自然恢复），但不重置或延长总休息倒计时。系统流程及休息期间允许拖动伙伴调整桌面位置（纯位移，不触发生气或落地动作）。
- 提醒音和哭闹音分别配置，默认关闭；用户可以选择内置声音或导入自己的 MP3、WAV 或 OGG 短音频。单个文件最多 20 MB，播放前 30 秒。对白配音使用独立的按伙伴开关和音量，不与提醒音或哭闹音共用设置。
- 开机自动启动默认关闭，用户可以在设置中开启。
- 完全离线保存照片、声音、宠物配置和提醒设置。

### 2.2 明确不包含

- 自动抠图、人脸识别或 AI 生成动作帧。
- 账号、云同步、遥测、广告或宠物包市场。
- 数值养成、喂食、成长值或复杂任务系统。
- 自由时间轴、关键帧或完整动画编辑器。
- 可组合对白、照片、动作或状态的自定义快捷互动、用户自定义转场或互动触发规则编辑器；常用对白只触发现有对白和已有配音，不属于可组合快捷互动。
- 自动更新服务。
- 正式商店发布、Windows 正式代码签名或 Apple Developer ID 公证。
- Linux 支持。

## 3. 目标平台与分发

- Windows 10/11，64 位。
- macOS 13 及以上，Intel 与 Apple Silicon。
- Windows 生成 x64 安装包。
- macOS 分别生成 x64 与 arm64 安装包。
- 推送 `v*` Git 标签后，GitHub Actions 构建安装包并创建草稿 GitHub Release。
- Release 包含安装包、SHA-256 校验值、版本说明和未签名应用安装指引。
- 第一版允许家人手动绕过 Windows SmartScreen 或 macOS Gatekeeper 提示。
- 构建配置预留未来代码签名和公证所需的环境变量，但仓库不保存证书或密码。

## 4. 技术路线

使用以下技术：

- Electron
- React
- TypeScript
- Vite
- electron-builder
- Vitest

选择 Electron 而非 Tauri 的主要原因是项目维护者熟悉 TypeScript、不熟悉 Rust。Electron 的透明窗口、置顶、托盘、窗口定位和跨平台打包能力足以覆盖需求。它的固定内存开销通过单常驻窗口、按需创建设置窗口、低频鼠标采样和待机动画节流进行控制。

## 5. 进程与模块架构

### 5.1 Electron 主进程

主进程只使用 TypeScript，负责系统能力和持久化。其模块边界如下：

- `AppController`：应用启动、单实例、生命周期和安全策略。
- `WindowManager`：创建宠物窗口与设置窗口，恢复位置，处理显示器变化。
- `TrayController`：托盘图标、菜单与显示/隐藏入口。
- `ReminderScheduler`：计算所有启用计划的下一次触发时间，处理延后、睡眠和时钟变化。
- `CompanionStateController`：管理自动生活节奏、手动生活状态、工作计划、系统流程覆盖与恢复。
- `RestSessionController`：管理休息会话、结束时间、鼠标采样和哭闹触发。
- `PetPackService`：导入、校验、复制和读取宠物素材及配置。
- `SettingsStore`：原子读写设置、备份上一份有效配置并执行 schema 迁移。
- `AudioService`：验证和播放提示音与哭闹音；失败时静默回退。
- `AutostartService`：查询、启用和停用随系统登录启动。

这些模块通过明确的 TypeScript 接口协作，避免将提醒、文件和窗口逻辑集中到一个大型主进程文件中。

### 5.2 Preload 桥接层

Preload 通过 `contextBridge` 暴露窄而类型安全的 API，例如：

- 读取宠物状态与设置。
- 请求导入图片或音频。
- 保存动作映射、提醒和偏好设置。
- 订阅宠物状态、提醒和休息会话事件。
- 请求移动、显示、隐藏或关闭窗口，以及选择允许的手动生活状态。
- 仅在摸头候选期间启动和停止受限的短时光标追踪，不暴露通用鼠标监听能力。

渲染层不直接获得 `ipcRenderer`、Node.js、文件系统或 shell 的通用访问权。每个 IPC 请求必须校验发送方、参数结构和资源标识符。

### 5.3 React 渲染层

- 宠物窗口：透明、无边框、跳过任务栏并保持置顶，只渲染宠物、照片转场、视觉叠层、气泡和倒计时。
- 设置窗口：普通窗口，按需创建；负责照片导入预览、生活用途与动作槽、头部热区、伙伴称呼与对白、工作计划、提醒列表、声音和常规设置。
- 设置窗口关闭后销毁，减少长期资源占用。
- 宠物动画以 CSS/Web Animations 的 `transform` 和 `opacity` 为主。

## 6. 宠物状态模型

运行时使用三层状态，避免为“工作中被点击”“睡觉中第一次被叫”等组合建立大量扁平状态。

### 6.1 系统流程层

系统流程层优先级最高：提醒气泡、休息中、哭闹和完成庆祝。系统流程出现时暂停生活节奏与普通互动（如单击反馈、摸头、自动卖萌），但允许通过鼠标拖拽移动伙伴与气泡（纯位移，不触发生气或落地动作）；结束后重新检查当前是否处于工作计划，再决定恢复工作或日常陪伴。

- `reminding`：切换到清醒表现并显示气泡，提供开始和延后选项。
- `resting`：显示休息素材或日常素材的呼吸效果，气泡下层工具栏持续稳定显示剩余倒计时。
- `crying`：休息期间鼠标移动超过容差时摇晃微颤、显示眼泪叠层和督促对白，可选播放声音；持续移动鼠标时顺延哭闹表现，手停约 3 秒后平滑恢复常态，下层倒计时保持独立稳定走动。
- `celebrating`：倒计时完成后播放庆祝动作，展示庆祝对白，再按当前时间恢复生活状态。

休息气泡采用分层解耦结构：上层专注展示提醒文案、督促对白或庆祝对白；下层工具栏左侧展示独立剩余倒计时（等宽数字 `剩余 mm:ss`），右侧提供“结束休息”按钮，保证督促对白出现时倒计时不消失、不抖动。

休息模式不锁定屏幕、不拦截鼠标或键盘。用户可以随时通过气泡“结束休息”按钮、宠物菜单或托盘结束本次休息；取消不产生惩罚性统计。

### 6.2 生活状态层

- `daily-calm`：使用平时陪伴照片，偶尔呼吸、点头或轻晃。
- `daily-playful`：仍使用平时陪伴照片，但动作和自动卖萌更活泼。
- `drowsy`：使用已启用的困倦照片；可以进入睡觉或回到日常。
- `sleeping`：使用已启用的睡觉照片；自动醒来或被连续点击叫醒。
- `working`：由工作计划或右键手动进入，使用工作照片或日常回退；不自动卖萌。
- `hidden`：宠物窗口隐藏，暂停生活节奏与视觉动画；托盘保持可用。

用户只需准备“平时陪伴”照片，不需要分别理解或配置空闲、玩耍照片。日常安静和日常活泼共享同一照片池。

工作由定时来源和手动来源共同决定；任一来源有效时保持工作。提醒可以覆盖工作表现，处理后若工作来源仍有效则恢复工作。

### 6.3 短动作层

短动作包括自动卖萌、单击反馈、摸头、连续点击叫醒、拖动、生气和照片转场。短动作结束后恢复原生活状态；成功叫醒会把生活状态正式切换为日常安静。

- 悬停只根据当前照片可见人物区域内的相对光标位置产生二维小位移与脚底轴轻微倾斜，不持续跨屏追踪。
- 单击按当前生活状态选择动画与对白；工作中幅度较小并保持工作。
- 睡觉期间的连续点击依次触发朦胧回应、加强反应和醒来；超时后叫醒进度清零。
- 摸头由头部热区附近的往返鼠标轨迹触发，不再依赖双击。
- 拖动速度超过阈值后触发生气、快速摇晃和抗议气泡，随后回到拖动前的生活状态。

伙伴动作默认将每张照片视为不可拆分的完整平面，不假设能够独立控制头、眼睛、肩膀或四肢。没有姿势匹配的替代照片时，不通过明显非等比缩放模拟具体肢体动作。普通整图变换以脚底基线为原点，并使用统一动作定义同步视觉时长与动作占用时间；详细动作池、交互映射和减少动态效果回退以 `2026-09-10-full-body-companion-motion-design.md` 为准。

总体优先级从高到低为：提醒与休息系统流程、工作、手动普通生活状态、自动生活状态、短暂视觉动作。高优先级状态出现时，低优先级动作安全结束或取消。

### 6.4 对白与称呼

首版按“当前生活场景 + 触发原因”提供内置对白库，并允许用户为每个伙伴分别设置对自己的称呼、查看和调整内置对白以及添加自己的对白。用户可以修改或停用内置对白、恢复当前版本的内置原文，并添加、修改、停用或删除自己的对白。场景和触发原因由程序固定，不提供触发规则、冷却时间或气泡时长编辑。

对白使用随机选择、短期防重复和分类冷却；自动对白频率低于主动互动，工作期间不自动出现卖萌对白。称呼通过界面提供的 `[称呼]` 占位符插入；称呼为空时，包含占位符的对白不参与选择。

用户可以整体关闭非必要互动气泡。关闭后不影响休息提醒、倒计时、错误消息或其他必须由用户操作的系统气泡。提醒计划的提示文案继续允许编辑。

用户可以为每个伙伴按加入顺序保存最多三句“常用对白”。常用对白允许引用已停用自动触发的内置或用户对白，但不允许引用休息督促与休息完成等系统对白；修改文字、配音或恢复内置原句时保留引用，删除用户对白时同步清理引用。伙伴右键菜单通过“常用对白”子菜单手动触发当前文字；日常对话气泡关闭或提醒与休息系统流程进行中时禁用，声音播放继续服从该伙伴的对白声音开关与音量。常用对白不切换照片、动作、生活状态或工作来源。

产品提供的内置对白采用可爱的小伙伴口吻，不声称自己是真实人物，不模拟真实家庭成员的具体记忆或言论。用户自己编写的私有对白不受产品语调约束，程序不做内容审核或自动改写。

所有用户可见中文文案区分产品声音与宠物声音。产品声音平静、直接、具体，不暴露状态机、动作槽、持久化或渲染器等实现概念；宠物声音短而贴合当前动作，不使用泛泛鼓励、机械卖萌或假装理解用户的 AI 助手口吻。菜单、设置、空状态、按钮、确认框、提醒、错误消息和宠物对白必须使用一致术语并完成整体审校，具体规则见 `2026-08-19-companion-presence-usability-design.md`。

## 7. 宠物包与素材处理

### 7.1 导入规则

- 只接受用户自己抠好的透明 PNG 或 WebP。
- 文件必须能够解码并包含透明通道。单张图片最多 20 MB、宽高均不超过 8192 px；单个宠物包最多 250 MB。
- 导入成功后，将素材复制到应用数据目录；后续不依赖原始文件路径，也不修改原文件。
- 应用重新生成内部文件名，避免路径遍历、冲突和特殊字符问题。

### 7.2 尺寸归一化

程序分析 alpha 边界，忽略全透明空白，然后根据人物可见高度计算缩放比例。所有素材默认对齐同一脚底基线并按目标人物高度渲染。

用户可以逐张微调：

- 缩放比例。
- 水平偏移。
- 垂直偏移和脚底基线。
- 可调整的椭圆形头部热区位置与大小；未调整时使用内置默认区域。

原图副本保持不变，调整结果以非破坏性元数据保存。

头部热区使用相对于图片可见区域的归一化中心坐标与半径保存。编辑器在可见区域上方生成一个可调整的初始估算；不做人脸识别。姿势差异较大的照片分别保存热区，不新增颈部基线。

### 7.3 生活照片与动作槽

用户可见的生活照片用途为：

- 平时陪伴：至少一张并始终启用。
- 有点困了：可选，照片存在且开关开启时可用。
- 睡觉：可选，照片存在且开关开启时可用。
- 陪伴工作：可选；缺失时使用日常照片回退，因此工作功能仍可用。

卖萌、生气、哭闹、休息和闭眼保留为可选短动作素材。摸头不提供独立动作素材设置，所有生活状态都只对当前照片播放缩放或点头动画，不切换图片。其他状态没有兼容短动作照片时，程序同样对当前照片播放内置动画，不跨状态借用姿势差异较大的照片。

### 7.4 动作回退

平时陪伴至少需要一张图片。其他生活用途与动作槽均为可选：

- 困倦缺失或关闭：直接跳过困倦。
- 睡觉缺失或关闭：困倦后返回日常，不进入睡觉。
- 工作缺失：日常图执行安静的工作动画并显示工作对白。
- 卖萌缺失：当前日常图执行弹跳或摇摆。
- 摸头：始终对当前生活照片执行缩放和点头，不读取独立动作素材。
- 生气缺失：当前生活照片快速摇晃并显示气泡。
- 哭闹缺失：当前生活照片叠加眼泪效果。
- 休息缺失：当前生活照片播放轻微呼吸。
- 闭眼帧缺失：不模拟眼皮，改为点头或呼吸。

如果用户提供与空闲姿势匹配的闭眼图片，程序以“睁眼、闭眼、睁眼”快速切换实现自然眨眼。第一版不做人脸定位或单图眼皮生成。

照片切换不直接硬切。日常照片池切换、进入或离开困倦、睡觉与工作，以及短动作更换照片时，统一使用约 400 毫秒的内置交叉淡化。程序先预加载新照片；加载成功后，旧照片淡出的同时新照片淡入。用户不能选择、关闭或编辑具体转场。新素材加载失败时保留旧照片，必要时回退到日常照片。

### 7.5 配置格式

宠物配置至少包含：

- `schemaVersion`
- 宠物 ID 与名称
- 默认人物高度
- 资产清单及内部文件标识
- 每张资产的 alpha 边界与对齐参数
- 每张资产可选的自定义头部热区；缺失时使用内置默认区域
- 生活照片用途、启用开关与动作槽到资产的映射
- 动作模板参数
- 陪伴节奏档位与互动气泡开关
- 每个伙伴独立的称呼、内置对白调整和用户对白
- 每个伙伴按加入顺序保存的最多三条常用对白稳定引用

工作计划与提醒计划一样属于全局设置，不随当前宠物切换。配置格式为将来的宠物包导入/导出保留版本化边界，但第一版不建设分享市场。

## 8. 提醒与休息流程

### 8.1 自动生活节奏与工作计划

用户只选择“安静、自然、爱玩”三个陪伴节奏档位，不逐项配置动作间隔、卖萌间隔或睡眠时长等数值。程序在各档内部使用随机时间范围，分别控制生命底噪、自主小动作、日常活泼期、自动卖萌、困倦和睡觉的出现频率。工作保留低频呼吸或眨眼，但停止自主位移、卖萌和主动对白；提醒、休息、宠物隐藏或系统睡眠时暂停自动节奏，恢复后重新计算且不补播积压动作。普通悬停和短交互只暂缓已经到期的普通动作，不重新抽取整段等待时间。

右键菜单显示当前陪伴状态，并使用“逗逗它”“安静陪我一会儿”“让它打个盹”“陪我专注”和“恢复自动陪伴”等用户意图语言。即时入口必须立即产生可见反馈，不允许只切换不可观察的内部状态。具体显示条件与工作来源语义见 `2026-08-19-companion-presence-usability-design.md`。

当前伙伴存在可解析的常用对白时，伙伴右键菜单在“逗逗它”之后通过上下分割线隔离出专属区域，直接平铺展示各句常用对白（超过 14 个可见字符的长对白末尾截断并补省略号，点击触发完整文字气泡），不再使用二级子菜单收纳；系统托盘菜单不显示该入口。子项使用引号包裹。菜单点击只显示气泡并按对白声音总开关播放已有配音，不改变当前生活状态或播放额外动作。

第一张成功导入的图片在当前没有日常照片时自动分配为“平时陪伴”。新用户可以在输入名称并导入一张合规图片后直接保存和显示宠物；素材归一化、头部热区和其他动作用途属于可后续调整的高级能力，不阻塞首次成功。

困倦和睡觉分别启用：只有睡觉可用时可以从日常直接睡觉；只有困倦可用时困倦后回到日常；两者都不可用时只在日常安静、日常活泼与卖萌短动作间轮换。自动醒来或被叫醒后进入内置最短清醒期，期间不会再次睡觉。

用户可以创建多个工作时段，分别设置开始时间、结束时间、重复星期和启用状态。结束时间早于开始时间时表示跨越午夜，重复星期指开始日；开始与结束时间相同的计划无效并拒绝保存。重叠时段中只要仍有一个有效就保持工作。手动工作和定时工作分别记录；右键结束工作只清除手动来源。应用启动、电脑唤醒、时区或系统时间变化时，根据当前当地时间重新判断工作状态，不补播错过的开始或结束事件。

普通手动生活状态只执行一轮正常时长后恢复自动陪伴。应用重启或电脑唤醒后不恢复玩耍、困倦、睡觉、普通手动状态或手动工作进度；若当前处于工作计划则进入工作，否则从日常安静开始。

### 8.2 默认行为

首次安装没有任何提醒计划。设置页显示“添加第一个提醒”的空状态引导，但不自动创建或保存示例计划。

用户新建提醒时配置：

- 提醒方式：固定时间，或时段内重复。
- 固定时间模式由用户明确选择一个提醒时间。
- 时段内重复模式配置统一的提醒间隔，以及一至三个互不重叠的当天时段；不支持跨午夜时段。
- 重复星期，建议值为每天。
- 休息时长，建议值为 10 分钟。
- 鼠标移动容差，建议值为“标准”。
- 提示文案，提供可编辑的内置建议文案。
- 提醒音和哭闹音，默认关闭。

保存后的新计划默认启用。用户可以添加多个计划，并随时编辑、停用或删除。

提醒编辑器使用明确的“指定时间”和“时段内重复”选项，不使用“普通”“高级”等模糊名称。默认只展示固定时间字段；选择时段内重复后，再展开提醒时段和提醒间隔：

- 每个时段使用独立的开始时间和结束时间输入；至少保留一个时段，最多添加三个。
- 同一计划的全部时段共享一个提醒间隔。不同间隔代表不同休息策略，应分别建立计划。
- 编辑过程中切换提醒方式时，暂时保留当前弹窗内尚未保存的输入；保存时只持久化所选模式的数据。
- 用户输入期间不自动调整时段顺序；保存后按开始时间规范化排序，避免聚焦中的表单行移动。
- 编辑器以一句自然语言汇总星期、时段和间隔，例如“周一至周五，09:00–12:00 和 14:00–18:00 期间，每 60 分钟提醒一次”。
- 时段的添加、移除和错误文案使用稳定槽位，不因条件内容出现或消失引起相邻表单跳动。
- 校验失败时显示轻量全局 Toast，并在对应字段下显示具体错误；不显示顶部错误摘要，焦点移至首个错误字段。
- 保存后的提醒列表直接展示固定时间，或全部时段范围，并通过独立标签展示“每 60 分钟”等间隔摘要。

### 8.3 调度语义

- 使用当地日历时间计算下一次触发，不使用固定 24 小时间隔。
- 时段内重复从每个时段的开始时间独立计算；开始时间本身触发，之后按统一间隔递增，只生成不晚于结束时间的实例。结束时间不与间隔点重合时不额外触发。
- 重复星期按每个时段所在的当地日期判断。时段必须在当天结束；需要跨午夜时由用户拆成两条计划。
- 提醒到点后显示宠物对话气泡。
- 用户可以立即开始、跳过本次提醒，或将当前提醒实例延后 5、10、15 分钟。
- 延后和跳过只影响当前实例，不修改重复计划。
- 同一条时段内重复计划已有活动气泡、排队实例或延后实例时，后续到点实例直接跳过，不形成积压；不同计划在同一时间触发时仍按稳定顺序依次处理。
- 任意休息会话进行期间到点的提醒直接跳过，不在休息结束后补弹。
- 电脑睡眠期间错过的提醒不会在唤醒后补弹，而是直接计算下一次计划。
- 时区、系统时间或夏令时变化时，重新计算所有启用计划并防止重复触发。

### 8.4 休息会话

- 开始时记录明确的 `startedAt` 与 `endsAt`。
- 界面按 `endsAt - now` 在气泡独立工具栏稳定显示剩余时间，避免定时器漂移，并在展示督促对白时保持稳定走动。
- 休息期间约每 250 ms 读取一次屏幕光标位置。
- 忽略单次极小抖动；在短时间窗口内累计有效移动距离。
- “标准”容差初始建议为累计约 24 DIP；具体值在跨平台实测后校准。
- 用户可选择“灵敏、标准、宽松”三档，不在第一版暴露任意数值输入。
- 超过阈值后进入哭闹状态（基础约 3 秒），清零累计移动量；若哭闹期间持续产生有效移动，则向后顺延哭闹状态与对白展示时长，手停约 3 秒后自然平滑恢复常态，消除重复闪烁与断层误判。
- 哭闹表现的顺延不会重置、暂停或延长总休息时间（`endsAt` 保持严格不变）。

### 8.5 睡眠与异常恢复

- 休息中电脑睡眠：唤醒后若已超过 `endsAt`，直接完成本次休息。
- 应用崩溃或被强制退出：下次启动保留配置和计划，但不恢复中断的休息会话。
- 显示器断开或分辨率变化：将宠物移动到主显示器可见范围。

## 9. 本地数据与错误处理

### 9.1 数据布局

所有数据位于 Electron `userData` 目录，逻辑上分为：

- 全局设置与提醒计划。
- 每个宠物的独立目录。
- 原始导入素材副本。
- 宠物配置和归一化元数据。
- 可选的本地诊断日志。

诊断日志不记录图片内容，不上传，不包含不必要的原始个人路径，并限制保留数量或时间。

### 9.2 写入策略

- 配置先写入同目录临时文件，刷新成功后原子替换正式文件。
- 每次替换前保留上一份可解析配置。
- 启动时若主配置损坏，尝试恢复上一份有效配置并向用户说明。
- schema 迁移在内存中验证成功后才写回磁盘。

### 9.3 失败行为

- 图片无透明通道、损坏或过大：只拒绝该文件，不影响已导入素材。
- 音频无法解码或播放：静默回退，并在设置页标记该音频不可用。
- 配置保存失败：保留旧配置，显示可理解的错误消息，并允许重试。
- 宠物渲染窗口崩溃：自动重建一次；重复失败时进入安全状态，保留托盘和设置入口。
- 提醒调度失败：记录本地错误，不创建重复计时器；设置页显示提醒服务异常。
- 当前生活状态的最后一张素材被移除或损坏：回到日常照片并停止该可选状态。
- 头部热区缺失或无效：回退到该照片的内置默认头部区域，不禁用摸头。
- 转场中的新素材加载失败：保留旧照片；旧照片也不可用时回到日常照片。
- 窗口位置无效：恢复到主显示器右下角的安全位置。

## 10. 安全与隐私

- 应用运行不需要网络；生产构建不包含远程页面、远程脚本、遥测或更新请求。
- 渲染进程设置 `nodeIntegration: false`、`contextIsolation: true` 和 `sandbox: true`。
- 配置严格的 Content Security Policy，只允许应用自身资源和受控的本地素材协议。
- 禁止任意导航、新窗口创建和未经校验的外部链接打开。
- 主进程验证每个 IPC 发送方、请求参数和资源标识。
- Preload 不暴露通用 IPC、文件系统、shell 或执行命令能力。
- 图片和音频作为数据解析，不执行用户导入文件中的代码或元数据脚本。
- 摸头候选期间的全局光标轨迹只保存在内存中，不写入配置或日志；Preload 不暴露通用全局鼠标监听接口。
- 依赖保持精简，并在维护周期内跟进受支持的 Electron 安全版本。

## 11. 性能策略与预算

- 只常驻一个宠物渲染窗口。
- 设置窗口仅在需要时创建，关闭后销毁。
- 空闲状态不持续播放 60 FPS 动画；呼吸、眨眼、点头和自主活动均以间歇短动作实现。
- 全局鼠标采样只在休息期间或鼠标进入头部热区后的短时摸头候选期间运行；两者互斥且休息流程优先。
- 动画优先使用 `transform` 和 `opacity`。
- 宠物隐藏、系统休眠或窗口不可见时暂停不必要的动画与计时工作。
- 图片与声音按需加载，并限制素材尺寸与总容量。
- 主进程只使用异步 I/O，不执行长时间同步任务。

软性能预算：

- 待机总内存目标不高于约 200 MB。
- 待机平均 CPU 目标低于 1%。
- 普通动作播放不出现明显卡顿或持续高 CPU。

预算受操作系统、硬件和 Electron 版本影响，因此作为跨平台实测目标，而不是逐台设备的绝对保证。

## 12. 测试策略

本节是不可协商的产品与工程约束，在计划、实现、评审和验收中都不得放宽、扩大或提出例外。自动化测试只覆盖必要的核心逻辑和可复用公共方法。不要求全面 TDD，不追求覆盖率数字，也不为 UI 或平台集成增加自动化测试框架。若工具、技能、模板或评审建议增加本节范围之外的测试，以本节为准并改用人工验收。

### 12.1 优先严格测试的逻辑

以下逻辑容易出现边界错误或会被多个模块复用，需要编写单元测试；适合时可采用 TDD：

- 宠物状态机和优先级切换。
- 自动生活节奏、最短清醒期、暂停与系统睡眠恢复。
- 工作计划的开始、结束、重叠、当地时间变化和提醒覆盖。
- 连续点击叫醒及超时清零。
- 摸头轨迹的距离、方向、速度、超时和误触过滤。
- 对白配置解析、称呼替换、有效池生成、冷却和短期防重复。
- 常用对白引用的数量与分类校验、精确解析、称呼替换、删除清理和 schema 迁移。
- 重复提醒下一次触发时间计算。
- 时段内重复提醒的多时段、间隔边界、星期过滤、时段排序和重叠校验。
- 延后、时区变化、夏令时和系统睡眠恢复。
- 活动气泡、排队实例、延后实例与后续间隔提醒重叠时的跳过和去重。
- 休息会话结束时间与倒计时计算。
- 鼠标抖动过滤、距离累计和阈值触发。
- 动作槽回退规则。
- 配置解析、头部热区校验、原子恢复和 schema 迁移。
- 图片与音频输入校验。
- 可复用的窗口几何、素材归一化和边界计算方法。

### 12.2 不做自动化测试的区域

- 不编写 UI 单元测试、React 组件测试或快照测试。
- 不引入 Playwright 或其他自动化端到端测试框架。
- 不打开或控制 Codex 内置浏览器、系统浏览器、本地网页预览或任何浏览器自动化工具来验证程序运行结果，也不以浏览器截图代替桌面应用验收。
- Agent 不执行也不声称完成任何 UI 验收；渲染界面、透明窗口、托盘、系统文件框、拖动手感、CSS 动画、安装包和操作系统安全提示全部由用户手动验收。
- Agent 的验证范围仅包括必要核心单元测试、lint、类型检查/构建，以及确认程序没有立即启动失败的非视觉 Electron 启动冒烟检查。Agent 不为观察或操作 UI 而启动 Electron。
- IPC 薄 wiring、平台适配器、简单展示组件、一次性样式和薄胶水代码不编写单元测试。

### 12.3 用户人工跨平台验收

所有 UI 和操作系统行为均由用户直接运行 Electron 应用手动验收。Agent 只在交付时提供简洁检查清单，并将这些项目明确标记为“等待用户验证”；不得根据单元测试、构建、截图或启动成功推断 UI 正确。该限制不禁止搜索技术文档或进行不涉及程序运行结果的资料检索。

每次发布至少在 Windows 与 macOS 验证：

- 安装、首次打开和未签名提示指引。
- 窗口透明、置顶、任务栏/Dock 行为和托盘。
- 状态化单击、连续点击叫醒、悬停、摸头、拖动和快速拖动反馈。
- 伙伴称呼、内置对白修改与恢复、用户对白编辑、场景分组和气泡预览。
- 常用对白的选择上限、跨场景汇总、右键子菜单、开关服从、配音播放和系统流程优先级。
- 日常节奏、困倦、睡觉、工作计划、右键手动状态和照片交叉淡化转场。
- 双屏、屏幕断开、缩放比例和位置恢复。
- 图片与音频导入。
- 固定时间提醒与时段内重复提醒的创建、编辑、模式切换、多时段增删、摘要和行内校验。
- 提醒、延后、休息、鼠标阈值、睡眠和完成流程；确认系统休眠、活动提醒、延后或休息期间不会积压间隔提醒。
- 开机启动启停。
- 待机及动作期间的内存和 CPU。
- 生产环境无网络请求。

### 12.4 执行与审查策略

本节与测试策略同样不可协商，且优先于技能、模板或评审工具的默认工作流：

- 每个里程碑由同一个执行者连续完成，并合并为 3–5 个内聚编码批次。
- 不使用逐任务子代理、逐任务 reviewer、双重 review、review ledger、review package 或重复修复/复审循环。
- 编码期间只运行受改动核心逻辑影响的定向单元测试；里程碑结束时统一运行允许的完整单元测试、lint、类型检查、生产构建和非视觉 Electron 启动冒烟检查，不执行 UI 验收。
- 全部编码和验证完成后，只针对里程碑完整 diff 做一次总 review，覆盖规格一致性、安全与隐私、跨模块集成和代码质量。
- review 问题合并为一次集中修复，然后统一复验；只有仍未解决的 Critical 或 Important 问题允许一次定向复审。
- 仅在规格冲突、新的安全/隐私/数据迁移决策、阻塞后续批次的接口歧义，或无法安全诊断的持续验证失败时中断批量执行。
- 不生成冗长逐任务报告，不重复粘贴未变化的上下文，只在批次完成、阻塞、最终验证和总 review 时简要汇报。

## 13. CI 与发布流程

### 13.1 Pull Request 检查

GitHub Actions 在 Windows 与 macOS 上按需执行：

- 安装锁定依赖。
- lint。
- TypeScript 类型检查。
- 核心逻辑与公共方法单元测试。
- Electron 生产构建检查。

单元测试可以根据平台价值分配到合适的 runner，避免无意义地重复所有任务。

### 13.2 标签发布

推送 `v*` 标签后：

1. 重新执行必要质量检查。
2. 使用 Windows runner 构建 Windows x64 安装包。
3. 使用 macOS runner 构建 macOS x64 与 arm64 安装包。
4. 计算 SHA-256。
5. 上传产物并创建草稿 GitHub Release。
6. 人工检查版本说明、安装指引和产物后再公开 Release。

第一版不自动更新。用户手动下载新版本安装包。

## 14. 第一版完成标准

- Windows 10/11 与 macOS 13+ 能安装、启动和退出。
- 用户能导入至少一张透明照片并完成尺寸归一化、日常用途分配、可选状态启停和头部热区调整。
- 默认约 180 px 的宠物能在桌面置顶显示、拖动、隐藏和恢复。
- 日常安静与活泼节奏、困倦、睡觉、最短清醒期和素材缺失回退按设计工作。
- 日常生命底噪、自主小动作、到期暂缓与恢复、减少动态效果回退及工作状态的低打扰生命感按设计工作。
- 状态化单击、连续点击叫醒、悬停、摸头、快速拖动、生气及短动作恢复按设计工作。
- 用户能创建、编辑、启停和删除工作计划，并能通过意图式右键菜单立即互动、临时安静陪伴、休息及进入或退出手动工作。
- 照片经过内置交叉淡化转场切换；用户能为每个伙伴设置称呼，查看、调整和恢复内置对白，并按场景添加自己的对白；自动对白具有冷却和短期防重复，并可整体关闭。
- 用户能为每个伙伴选择最多三句常用对白，并从伙伴右键菜单显示当前文字和按总开关播放已有配音，不影响伙伴当前状态。
- 无闭眼素材时安全回退；有匹配闭眼素材时能自然眨眼。
- 首次安装没有提醒；用户能创建、编辑、启停和删除提醒。
- 提醒、延后、休息倒计时、鼠标移动容差、哭闹和完成流程工作。
- 声音默认关闭，可独立设置并在失败时回退。
- 应用完全离线，个人素材不会离开本机。
- 配置写入失败或损坏不会破坏上一份有效数据。
- 核心逻辑与公共方法单元测试通过，跨平台人工验收通过。
- GitHub Actions 能产生 Windows 与两种 macOS 架构的 Release 产物。
- 待机资源占用达到软性能预算，或记录可接受的实测偏差与原因。
