# Dear Companion 桌面宠物设计规格

日期：2026-07-31

## 1. 产品目标

Dear Companion 是一款面向 Windows 和 macOS 的离线桌面宠物应用。用户导入自己已经抠好、带透明背景的人物照片，将其配置为会卖萌、响应鼠标互动并邀请用户休息的桌面伙伴。

第一版面向家人和少量朋友分发。应用不需要账号、不连接云端，也不上传照片、声音或配置。用户通过安装包使用应用；GitHub Actions 自动构建发布产物。

第一版的核心价值是：只用少量静态人物照片，也能得到自然、轻量、可配置的桌面陪伴体验。

## 2. 第一版范围

### 2.1 包含功能

- 透明、无边框、置顶的桌面宠物窗口。
- 默认人物显示高度约 180 px，可在 80–260 px 范围内缩放。
- 自动保存宠物在桌面上的位置，并确保它始终位于某块可见屏幕内。
- 单击随机卖萌，双击触发“摸摸”反馈。
- 鼠标悬停时，宠物朝光标方向轻微倾斜或转动。
- 用户可以拖动宠物；拖动过快时宠物会短暂生气抗议。
- 右键菜单和系统托盘提供显示、隐藏、设置和退出等操作。
- 用户导入透明 PNG 或 WebP，程序负责透明边距裁切、视觉高度归一化、脚底基线对齐和预览微调。
- 用户将照片分配给空闲、卖萌、摸摸、生气、哭闹、休息和闭眼等动作槽。
- 内置呼吸、点头、弹跳、摇晃、倾斜和照片切换等动作模板。
- 支持多个用户自建提醒计划；首次安装的提醒列表为空。
- 提醒到点后，宠物通过对话气泡邀请用户立即开始或延后 5、10、15 分钟。
- 休息期间宠物坐下或打盹，并通过气泡显示剩余时间。
- 休息期间检测鼠标移动；超过容差后宠物哭闹，但不重置或延长倒计时。
- 提醒音和哭闹音分别配置，默认关闭；用户可以选择内置声音或导入自己的 MP3、WAV 或 OGG 短音频。单个文件最多 20 MB，播放前 30 秒。
- 开机自动启动默认关闭，用户可以在设置中开启。
- 完全离线保存照片、声音、宠物配置和提醒设置。

### 2.2 明确不包含

- 自动抠图、人脸识别或 AI 生成动作帧。
- 账号、云同步、遥测、广告或宠物包市场。
- 数值养成、喂食、成长值或复杂任务系统。
- 自由时间轴、关键帧或完整动画编辑器。
- 自动更新服务。
- 正式商店发布、Windows 正式代码签名或 Apple Developer ID 公证。
- Linux 支持。

## 3. 目标平台与分发

- Windows 10/11，64 位。
- macOS 13 及以上，Intel 与 Apple Silicon。
- Windows 生成 x64 安装包。
- macOS 分别生成 x64 与 arm64 安装包。
- 推送 `v*` Git 标签后，GitHub Actions 构建安装包并创建草稿 GitHub Release。
- Release 包含安装包、SHA-256 校验值、版本说明和未签名应用安装指引。
- 第一版允许家人手动绕过 Windows SmartScreen 或 macOS Gatekeeper 提示。
- 构建配置预留未来代码签名和公证所需的环境变量，但仓库不保存证书或密码。

## 4. 技术路线

使用以下技术：

- Electron
- React
- TypeScript
- Vite
- electron-builder
- Vitest

选择 Electron 而非 Tauri 的主要原因是项目维护者熟悉 TypeScript、不熟悉 Rust。Electron 的透明窗口、置顶、托盘、窗口定位和跨平台打包能力足以覆盖需求。它的固定内存开销通过单常驻窗口、按需创建设置窗口、低频鼠标采样和待机动画节流进行控制。

## 5. 进程与模块架构

### 5.1 Electron 主进程

主进程只使用 TypeScript，负责系统能力和持久化。其模块边界如下：

- `AppController`：应用启动、单实例、生命周期和安全策略。
- `WindowManager`：创建宠物窗口与设置窗口，恢复位置，处理显示器变化。
- `TrayController`：托盘图标、菜单与显示/隐藏入口。
- `ReminderScheduler`：计算所有启用计划的下一次触发时间，处理延后、睡眠和时钟变化。
- `RestSessionController`：管理休息会话、结束时间、鼠标采样和哭闹触发。
- `PetPackService`：导入、校验、复制和读取宠物素材及配置。
- `SettingsStore`：原子读写设置、备份上一份有效配置并执行 schema 迁移。
- `AudioService`：验证和播放提示音与哭闹音；失败时静默回退。
- `AutostartService`：查询、启用和停用随系统登录启动。

这些模块通过明确的 TypeScript 接口协作，避免将提醒、文件和窗口逻辑集中到一个大型主进程文件中。

### 5.2 Preload 桥接层

Preload 通过 `contextBridge` 暴露窄而类型安全的 API，例如：

- 读取宠物状态与设置。
- 请求导入图片或音频。
- 保存动作映射、提醒和偏好设置。
- 订阅宠物状态、提醒和休息会话事件。
- 请求移动、显示、隐藏或关闭窗口。

渲染层不直接获得 `ipcRenderer`、Node.js、文件系统或 shell 的通用访问权。每个 IPC 请求必须校验发送方、参数结构和资源标识符。

### 5.3 React 渲染层

- 宠物窗口：透明、无边框、跳过任务栏并保持置顶，只渲染宠物、视觉叠层、气泡和倒计时。
- 设置窗口：普通窗口，按需创建；负责照片导入预览、动作槽、提醒列表、声音和常规设置。
- 设置窗口关闭后销毁，减少长期资源占用。
- 宠物动画以 CSS/Web Animations 的 `transform` 和 `opacity` 为主。

## 6. 宠物状态机

任意时刻只有一个主要状态。状态优先级从高到低为：

1. 休息中与哭闹
2. 休息提醒气泡
3. 拖动与生气
4. 单击/双击触发的短动作
5. 悬停关注光标
6. 空闲陪伴

高优先级状态出现时，低优先级动画安全结束或被取消。

### 6.1 日常状态

- `idle`：显示空闲素材，偶尔呼吸、点头、轻晃或卖萌。
- `hovering`：根据宠物窗口内的相对光标位置轻微倾斜，不跨屏追踪光标。
- `performingAction`：播放卖萌或摸摸动作，结束后回到空闲。
- `dragging`：宠物跟随鼠标移动，释放后保存位置。
- `angry`：拖动速度超过阈值后快速摇晃并显示抗议气泡，随后回到空闲。
- `hidden`：宠物窗口隐藏，停止视觉动画；托盘保持可用。

### 6.2 提醒与休息状态

- `reminding`：显示宠物对话气泡，提供开始和延后选项。
- `resting`：显示休息素材或空闲素材的呼吸效果，并持续显示倒计时。
- `crying`：超过鼠标移动容差时短暂摇晃、显示眼泪叠层和气泡，可选播放声音。
- `celebrating`：倒计时完成后播放庆祝动作，再回到空闲。

休息模式不锁定屏幕、不拦截鼠标或键盘。用户可以随时通过宠物菜单或托盘结束本次休息；取消不产生惩罚性统计。

## 7. 宠物包与素材处理

### 7.1 导入规则

- 只接受用户自己抠好的透明 PNG 或 WebP。
- 文件必须能够解码并包含透明通道。单张图片最多 20 MB、宽高均不超过 8192 px；单个宠物包最多 250 MB。
- 导入成功后，将素材复制到应用数据目录；后续不依赖原始文件路径，也不修改原文件。
- 应用重新生成内部文件名，避免路径遍历、冲突和特殊字符问题。

### 7.2 尺寸归一化

程序分析 alpha 边界，忽略全透明空白，然后根据人物可见高度计算缩放比例。所有素材默认对齐同一脚底基线并按目标人物高度渲染。

用户可以逐张微调：

- 缩放比例。
- 水平偏移。
- 垂直偏移和脚底基线。

原图副本保持不变，调整结果以非破坏性元数据保存。

### 7.3 动作槽与回退

空闲槽至少需要一张图片。其他动作槽均为可选：

- 卖萌缺失：空闲图执行弹跳或摇摆。
- 摸摸缺失：空闲图执行缩放和点头。
- 生气缺失：空闲图快速摇晃并显示气泡。
- 哭闹缺失：空闲图叠加眼泪效果。
- 休息缺失：空闲图播放轻微呼吸。
- 闭眼帧缺失：不模拟眼皮，改为点头或呼吸。

如果用户提供与空闲姿势匹配的闭眼图片，程序以“睁眼、闭眼、睁眼”快速切换实现自然眨眼。第一版不做人脸定位或单图眼皮生成。

### 7.4 配置格式

宠物配置至少包含：

- `schemaVersion`
- 宠物 ID 与名称
- 默认人物高度
- 资产清单及内部文件标识
- 每张资产的 alpha 边界与对齐参数
- 动作槽到资产的映射
- 动作模板参数

配置格式为将来的宠物包导入/导出保留版本化边界，但第一版不建设分享市场。

## 8. 提醒与休息流程

### 8.1 默认行为

首次安装没有任何提醒计划。设置页显示“添加第一个提醒”的空状态引导，但不自动创建或保存示例计划。

用户新建提醒时配置：

- 提醒时间，由用户明确选择。
- 重复星期，建议值为每天。
- 休息时长，建议值为 10 分钟。
- 鼠标移动容差，建议值为“标准”。
- 提示文案，提供可编辑的内置建议文案。
- 提醒音和哭闹音，默认关闭。

保存后的新计划默认启用。用户可以添加多个计划，并随时编辑、停用或删除。

### 8.2 调度语义

- 使用当地日历时间计算下一次触发，不使用固定 24 小时间隔。
- 提醒到点后显示宠物对话气泡。
- 用户可以立即开始，或将当前提醒实例延后 5、10、15 分钟。
- 延后只影响当前实例，不修改重复计划。
- 电脑睡眠期间错过的提醒不会在唤醒后补弹，而是直接计算下一次计划。
- 时区、系统时间或夏令时变化时，重新计算所有启用计划并防止重复触发。

### 8.3 休息会话

- 开始时记录明确的 `startedAt` 与 `endsAt`。
- 界面按 `endsAt - now` 显示剩余时间，避免定时器漂移。
- 休息期间约每 250 ms 读取一次屏幕光标位置。
- 忽略单次极小抖动；在短时间窗口内累计有效移动距离。
- “标准”容差初始建议为累计约 24 DIP；具体值在跨平台实测后校准。
- 用户可选择“灵敏、标准、宽松”三档，不在第一版暴露任意数值输入。
- 超过阈值后进入约 3 秒哭闹状态，清零累计移动量，然后继续原倒计时。
- 哭闹不会重置、暂停或延长休息时间。

### 8.4 睡眠与异常恢复

- 休息中电脑睡眠：唤醒后若已超过 `endsAt`，直接完成本次休息。
- 应用崩溃或被强制退出：下次启动保留配置和计划，但不恢复中断的休息会话。
- 显示器断开或分辨率变化：将宠物移动到主显示器可见范围。

## 9. 本地数据与错误处理

### 9.1 数据布局

所有数据位于 Electron `userData` 目录，逻辑上分为：

- 全局设置与提醒计划。
- 每个宠物的独立目录。
- 原始导入素材副本。
- 宠物配置和归一化元数据。
- 可选的本地诊断日志。

诊断日志不记录图片内容，不上传，不包含不必要的原始个人路径，并限制保留数量或时间。

### 9.2 写入策略

- 配置先写入同目录临时文件，刷新成功后原子替换正式文件。
- 每次替换前保留上一份可解析配置。
- 启动时若主配置损坏，尝试恢复上一份有效配置并向用户说明。
- schema 迁移在内存中验证成功后才写回磁盘。

### 9.3 失败行为

- 图片无透明通道、损坏或过大：只拒绝该文件，不影响已导入素材。
- 音频无法解码或播放：静默回退，并在设置页标记该音频不可用。
- 配置保存失败：保留旧配置，显示可理解的错误消息，并允许重试。
- 宠物渲染窗口崩溃：自动重建一次；重复失败时进入安全状态，保留托盘和设置入口。
- 提醒调度失败：记录本地错误，不创建重复计时器；设置页显示提醒服务异常。
- 窗口位置无效：恢复到主显示器右下角的安全位置。

## 10. 安全与隐私

- 应用运行不需要网络；生产构建不包含远程页面、远程脚本、遥测或更新请求。
- 渲染进程设置 `nodeIntegration: false`、`contextIsolation: true` 和 `sandbox: true`。
- 配置严格的 Content Security Policy，只允许应用自身资源和受控的本地素材协议。
- 禁止任意导航、新窗口创建和未经校验的外部链接打开。
- 主进程验证每个 IPC 发送方、请求参数和资源标识。
- Preload 不暴露通用 IPC、文件系统、shell 或执行命令能力。
- 图片和音频作为数据解析，不执行用户导入文件中的代码或元数据脚本。
- 依赖保持精简，并在维护周期内跟进受支持的 Electron 安全版本。

## 11. 性能策略与预算

- 只常驻一个宠物渲染窗口。
- 设置窗口仅在需要时创建，关闭后销毁。
- 空闲状态不持续播放 60 FPS 动画，只间歇播放短动作。
- 全局鼠标采样只在休息期间运行。
- 动画优先使用 `transform` 和 `opacity`。
- 宠物隐藏、系统休眠或窗口不可见时暂停不必要的动画与计时工作。
- 图片与声音按需加载，并限制素材尺寸与总容量。
- 主进程只使用异步 I/O，不执行长时间同步任务。

软性能预算：

- 待机总内存目标不高于约 200 MB。
- 待机平均 CPU 目标低于 1%。
- 普通动作播放不出现明显卡顿或持续高 CPU。

预算受操作系统、硬件和 Electron 版本影响，因此作为跨平台实测目标，而不是逐台设备的绝对保证。

## 12. 测试策略

本节是不可协商的产品与工程约束，在计划、实现、评审和验收中都不得放宽、扩大或提出例外。自动化测试只覆盖必要的核心逻辑和可复用公共方法。不要求全面 TDD，不追求覆盖率数字，也不为 UI 或平台集成增加自动化测试框架。若工具、技能、模板或评审建议增加本节范围之外的测试，以本节为准并改用人工验收。

### 12.1 优先严格测试的逻辑

以下逻辑容易出现边界错误或会被多个模块复用，需要编写单元测试；适合时可采用 TDD：

- 宠物状态机和优先级切换。
- 重复提醒下一次触发时间计算。
- 延后、时区变化、夏令时和系统睡眠恢复。
- 休息会话结束时间与倒计时计算。
- 鼠标抖动过滤、距离累计和阈值触发。
- 动作槽回退规则。
- 配置解析、原子恢复和 schema 迁移。
- 图片与音频输入校验。
- 可复用的窗口几何、素材归一化和边界计算方法。

### 12.2 不做自动化测试的区域

- 不编写 UI 单元测试、React 组件测试或快照测试。
- 不引入 Playwright 或其他自动化端到端测试框架。
- 不打开或控制 Codex 内置浏览器、系统浏览器、本地网页预览或任何浏览器自动化工具来验证程序运行结果，也不以浏览器截图代替桌面应用验收。
- 渲染界面、透明窗口、托盘、系统文件框、拖动手感、CSS 动画、安装包和操作系统安全提示通过人工验收。
- IPC 薄 wiring、平台适配器、简单展示组件、一次性样式和薄胶水代码不编写单元测试。

### 12.3 人工跨平台验收

人工验收必须直接运行 Electron 应用，不得改用浏览器验证；当前环境无法完成的操作系统检查应明确记录为“未执行”。该限制不禁止搜索技术文档或进行不涉及程序运行结果的资料检索。

每次发布至少在 Windows 与 macOS 验证：

- 安装、首次打开和未签名提示指引。
- 窗口透明、置顶、任务栏/Dock 行为和托盘。
- 单击、双击、悬停、拖动和快速拖动反馈。
- 双屏、屏幕断开、缩放比例和位置恢复。
- 图片与音频导入。
- 提醒、延后、休息、鼠标阈值、睡眠和完成流程。
- 开机启动启停。
- 待机及动作期间的内存和 CPU。
- 生产环境无网络请求。

### 12.4 执行与审查策略

本节与测试策略同样不可协商，且优先于技能、模板或评审工具的默认工作流：

- 每个里程碑由同一个执行者连续完成，并合并为 3–5 个内聚编码批次。
- 不使用逐任务子代理、逐任务 reviewer、双重 review、review ledger、review package 或重复修复/复审循环。
- 编码期间只运行受改动核心逻辑影响的定向单元测试；里程碑结束时统一运行允许的完整单元测试、lint、类型检查、生产构建和必要人工检查。
- 全部编码和验证完成后，只针对里程碑完整 diff 做一次总 review，覆盖规格一致性、安全与隐私、跨模块集成和代码质量。
- review 问题合并为一次集中修复，然后统一复验；只有仍未解决的 Critical 或 Important 问题允许一次定向复审。
- 仅在规格冲突、新的安全/隐私/数据迁移决策、阻塞后续批次的接口歧义，或无法安全诊断的持续验证失败时中断批量执行。
- 不生成冗长逐任务报告，不重复粘贴未变化的上下文，只在批次完成、阻塞、最终验证和总 review 时简要汇报。

## 13. CI 与发布流程

### 13.1 Pull Request 检查

GitHub Actions 在 Windows 与 macOS 上按需执行：

- 安装锁定依赖。
- lint。
- TypeScript 类型检查。
- 核心逻辑与公共方法单元测试。
- Electron 生产构建检查。

单元测试可以根据平台价值分配到合适的 runner，避免无意义地重复所有任务。

### 13.2 标签发布

推送 `v*` 标签后：

1. 重新执行必要质量检查。
2. 使用 Windows runner 构建 Windows x64 安装包。
3. 使用 macOS runner 构建 macOS x64 与 arm64 安装包。
4. 计算 SHA-256。
5. 上传产物并创建草稿 GitHub Release。
6. 人工检查版本说明、安装指引和产物后再公开 Release。

第一版不自动更新。用户手动下载新版本安装包。

## 14. 第一版完成标准

- Windows 10/11 与 macOS 13+ 能安装、启动和退出。
- 用户能导入至少一张透明照片并完成尺寸归一化与动作分配。
- 默认约 180 px 的宠物能在桌面置顶显示、拖动、隐藏和恢复。
- 单击、双击、悬停、快速拖动及动作回退按设计工作。
- 无闭眼素材时安全回退；有匹配闭眼素材时能自然眨眼。
- 首次安装没有提醒；用户能创建、编辑、启停和删除提醒。
- 提醒、延后、休息倒计时、鼠标移动容差、哭闹和完成流程工作。
- 声音默认关闭，可独立设置并在失败时回退。
- 应用完全离线，个人素材不会离开本机。
- 配置写入失败或损坏不会破坏上一份有效数据。
- 核心逻辑与公共方法单元测试通过，跨平台人工验收通过。
- GitHub Actions 能产生 Windows 与两种 macOS 架构的 Release 产物。
- 待机资源占用达到软性能预算，或记录可接受的实测偏差与原因。
