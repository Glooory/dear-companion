# Dear Companion 常用对白设计

日期：2026-09-08

## 1. 目标与范围

用户可以为每个伙伴分别选出最多三句“常用对白”，并从伙伴的右键菜单手动让当前伙伴说出其中一句。触发后只显示该句当前保存的文字，并在对白声音总开关开启且该句具有可用配音时播放已有配音；不切换照片、动作或生活状态。

本功能复用现有对白编辑、称呼替换、气泡显示、按句配音、音量、截取范围与播放失败回退，不增加新的音频来源、文件格式、网络能力或后台服务。

本次包含：

- 内置对白和用户对白均可设为常用；每个伙伴最多三句。
- 已停用自动触发的对白仍可设为常用，因为自动出现与手动触发是两个独立意图。
- 设置页显示常用对白汇总、已选数量与每句对白的选择状态。
- 伙伴右键菜单显示“常用对白”子菜单，子项使用该句解析称呼后的完整当前文字。
- 编辑文字、配音、截取范围或音量后，菜单在下次打开时使用最新保存值。
- 删除用户对白时同步移除其常用引用；恢复内置对白时保留其常用引用。

本次不包含：

- 为常用对白绑定照片、动作、生活状态或自定义触发条件。
- 全局键盘快捷键、托盘菜单入口、常用对白搜索、分组、拖拽排序或可配置数量上限。
- 将“休息督促”或“休息结束”系统对白设为常用。

## 2. 设置页交互

“对白与称呼”页顶部控制卡片中增加“常用对白”区域。区域始终显示 `已选 n / 3`，并按加入顺序显示最多三个汇总项。空位不制造额外操作，只通过数量与说明表达容量。说明文案为“选出最多 3 句，在伙伴的右键菜单中随时播放。”

每条可选对白的操作区增加一个固定宽度的状态按钮：未选择时为“设为常用”，已选择时为“已设为常用”。按钮使用一致的矢量图钉图标，选中状态不能只依赖颜色，并通过 `aria-pressed` 暴露状态。按钮文字或图标状态变化不能改变对白行的高度、操作区宽度或相邻内容位置。

达到三句后，其他未选择对白的按钮使用原生禁用语义和清晰的弱化外观；已选择对白仍可取消。汇总区使用固定高度的状态槽显示“已经选满，取消一句后可以继续添加。”，不额外弹出 Toast。窄窗口允许操作区自然换行，但不能遮挡输入框、配音操作或键盘焦点。

汇总项显示解析称呼后的当前对白文字并提供取消操作。长文字可以在汇总项中截断，但必须通过可访问名称和原生标题提供完整文本；右键菜单中显示完整文本。首版按加入顺序排列，不提供排序控件。

以下对白不能被设为常用：

- `rest:crying`
- `rest:completion`
- 空文字或当前校验不通过的对白。
- 包含 `[称呼]` 但当前伙伴称呼为空的对白。

如果已选对白因后续编辑变成空文字、重复文字或缺少称呼，保存时在常用对白汇总区显示具体行内错误，并把焦点移到对应对白输入或称呼输入。保存校验仍只使用现有轻量全局 Toast 加具体行内错误，不增加顶部错误摘要。

删除用户对白时直接清理对应常用引用，不显示二次确认之外的额外提示。停用自动触发、修改文字、修改配音和恢复内置原句均不改变常用状态。

## 3. 右键菜单与触发行为

当前伙伴至少有一句可解析的常用对白时，伙伴右键菜单在“逗逗它”之后显示“常用对白”子菜单。每个子项使用中文引号包裹完整对白，例如 `“今天也辛苦啦。”`，用于区分宠物对白与菜单命令。子项顺序与设置页加入顺序一致。

常用对白只出现在伙伴右键菜单，不加入系统托盘菜单。没有常用对白时不显示空子菜单。

以下情况保留“常用对白”入口但禁用：

- “日常对话气泡”总开关关闭。
- 提醒、休息、哭闹或完成庆祝等系统流程正在进行。

专注、困倦、睡觉或其他普通生活状态不禁用常用对白，因为这是用户明确发起的短暂表达。触发不会改变当前生活状态、手动状态选择、工作来源或照片，也不额外播放点头、弹跳等动作。

点击子项后立即用当前伙伴显示该句气泡，持续时间沿用普通对白的现有时长。若“对白声音”开启且该句具有可用配音，则沿用当前伙伴的对白音量、截取范围、约 80 ms 延迟起播与约 50 ms 旧声音淡出。声音关闭、缺失、不可用或播放失败时仍显示气泡，并静默跳过声音。

主进程每次打开菜单时从已验证的当前设置解析常用对白，不接受渲染器传入任意文字、声音路径或文件标识。菜单点击通过现有窄类型的主进程到宠物渲染器交互事件发送已经解析的文字和可选配音元数据；不新增通用 IPC、文件系统或 shell 能力。

## 4. 数据与迁移

应用设置 schema 从 V7 升级为 V8。每个伙伴的 `dialogueSettings` 增加：

```ts
interface QuickDialogueReference {
  category: DialogueCategory;
  lineId: string;
}

interface PetDialogueSettings {
  address: string;
  categories: Readonly<Partial<Record<DialogueCategory, DialogueCategorySettings>>>;
  voiceEnabled: boolean;
  voiceVolume: number;
  quickDialogueRefs: readonly QuickDialogueReference[];
}
```

V7 及更早受支持版本迁移到 V8 时，所有伙伴的 `quickDialogueRefs` 默认为空数组，现有提醒、照片、对白、配音与其他设置保持不变。解析器要求引用数量不超过三、分类有效、分类不属于两个休息系统分类、`lineId` 为安全标识符且 `{ category, lineId }` 不重复。

为兼容未来内置对白目录变化，配置解析允许安全但已经不存在的行 ID；解析菜单候选时忽略无法找到的陈旧引用。设置页保存当前伙伴时会清理已经删除的用户对白引用。解析后的数组、克隆和快照不得与输入共享可变引用。

对白解析提供独立的精确引用函数，不复用会过滤 `automaticEnabled: false` 的自动对白候选池。精确解析应用当前文字覆盖、称呼替换、配音 ID 与截取范围。多个常用引用解析为相同最终文字时保存失败，避免右键菜单出现无法区分的同名项。

## 5. 错误处理与边界

- 菜单打开期间伙伴被删除、切换或窗口销毁：放弃本次菜单或点击请求，不向陈旧窗口发送事件。
- 引用找不到、文字为空或称呼无法替换：忽略该菜单子项，不影响其他常用对白。
- 声音文件缺失或播放失败：继续显示文字，沿用现有声音失败清理。
- 配置保存失败：保留上一次已保存的菜单内容与配置，设置页保留当前草稿供用户重试。
- 同一句对白连续触发：新气泡替换旧气泡，旧声音按现有协调器逻辑停止或淡出。

## 6. 测试与验收

自动化测试只覆盖必要核心逻辑和可复用共享方法：

- V7 到 V8 迁移、默认空引用、严格数量/分类/标识符/重复引用校验与深克隆。
- 按稳定引用解析内置对白、用户对白、已停用自动对白、文字覆盖、称呼、配音和截取范围。
- 缺失引用、禁用系统分类、空文字、缺少称呼和重复最终文字的处理。
- 删除用户对白时清理引用，恢复或修改对白时保留引用。

不添加 UI 单元测试、React 组件测试、快照测试、浏览器测试或自动化端到端测试。完成时执行允许的完整单元测试、lint、类型检查、生产构建和非视觉 Electron 启动冒烟检查。

以下项目等待用户在 Windows 和 macOS 手动验证：

- 设置页数量、汇总项、按钮状态和选满提示清楚，键盘操作与焦点可用。
- 按钮、汇总项和提示出现或变化时不引起累积布局位移。
- 不同场景页签中的选择能在汇总区统一看到并取消。
- 右键菜单子菜单的显示位置、禁用状态、完整文字、顺序和本地化标点正确。
- 气泡开关、声音开关、配音有无、音量、截取、声音文件缺失和快速连续触发符合设计。
- 提醒与休息流程优先，专注、困倦和睡觉状态不被常用对白改变。
- 切换伙伴后显示各自独立的常用对白。
