# Dear Companion 陪伴感与易用性优化设计

日期：2026-08-19

## 1. 目标

本次优化解决四个首要问题：宠物长时间完全静止、自动动作容易因普通交互被反复延后、右键菜单和陪伴节奏对新用户缺少可预期含义，以及程序文案偏技术化、含糊或带有模板化的 AI 口吻。

优化后的体验应让用户感到宠物持续存在、偶尔主动活动、很少打断工作。首版继续保持完全离线，不增加账号、遥测、数值养成、自定义对白、AI 图片处理或新的云服务。

## 2. 分层陪伴模型

自主表现分为三个层次，分别解决生命感、主动性和性格表达。

### 2.1 生命底噪

生命底噪是无气泡、无照片切换、通常不移动窗口的短动作，包括呼吸、眨眼、轻微点头和重心变化。

- 安静档每 12–20 秒尝试一次。
- 自然档每 8–14 秒尝试一次。
- 爱玩档每 5–10 秒尝试一次。
- 一次只播放一个短动作，结束后回到静止姿势。
- 有闭眼素材时优先偶尔播放自然眨眼；没有时在呼吸、点头和轻晃中回退，不模拟眼皮。
- 工作中仍保留低频呼吸或眨眼，间隔为 12–20 秒，不自动说话或移动窗口。
- 困倦和睡觉使用与状态一致的轻呼吸或轻晃，不播放活泼动作。
- 系统启用“减少动态效果”时不播放位移、弹跳或摇晃，只保留低幅呼吸或素材眨眼。

生命底噪采用间歇短动画，不持续运行 60 FPS 动画循环；窗口隐藏、页面不可见、系统流程覆盖或系统休眠时暂停。

### 2.2 自主小动作

自主小动作用于表达宠物会自行活动，包括轻晃、左右走几步和短暂观察。

- 安静档每 2–4 分钟尝试一次。
- 自然档每 45–120 秒尝试一次。
- 爱玩档每 25–70 秒尝试一次。
- 单次自主位移目标为约 12–30 DIP，并始终限制在当前显示器工作区内。
- 自主小动作默认不显示气泡；同一时间只能有一个短动作。
- 工作、困倦、睡觉、提醒和休息流程中不进行自主位移。

自动调度保存明确的截止时间。鼠标悬停、一次点击或其他短动作只暂缓当前执行，不重新抽取整段等待时间；恢复空闲 1–3 秒后执行已经到期的动作。隐藏、系统休眠、工作和系统流程仍按原规格暂停并在恢复时重新计算，不补播一串积压动作。

### 2.3 性格事件

性格事件包括卖萌、明显动作、换照片、困倦、睡觉和主动对白。

- 自动卖萌继续使用现有档位范围：安静 8–16 分钟、自然 4–10 分钟、爱玩 2–6 分钟。
- 自动对白比动作更稀少；并非每次卖萌都必须说话。
- 日常活泼期提高动作组合的活跃程度，而不仅改变内部状态名。
- 进入困倦、睡觉、工作和从这些状态返回时继续提供与场景一致的可见反馈。
- 工作期间不发生卖萌、主动对白或自主位移。

## 3. 右键菜单

右键菜单使用用户意图而不是内部状态名称，并在顶部显示不可点击的当前状态：

- `现在：自动陪伴 · 安静/自然/爱玩`
- `现在：安静陪伴`
- `现在：专注陪伴`
- `现在：休息中` 等系统状态

普通入口按以下顺序显示：

1. `逗逗它`：立即播放一次与当前日常状态兼容的明显互动，并给出即时视觉反馈；不创建长期手动状态。
2. `安静陪我一会儿`：进入一轮日常安静状态，保留生命底噪，停止主动对白和自主位移；结束后恢复自动陪伴。
3. `让它打个盹`：睡觉素材可用时显示并直接进入一轮睡觉；只有困倦素材可用时改为 `让它歇一会儿` 并进入困倦。
4. `陪我专注` / `结束专注陪伴`：控制手动工作来源；定时工作来源仍按原规则生效。
5. `恢复自动陪伴`：仅在普通手动状态生效时显示，用于立即取消手动覆盖。

系统流程期间禁用不适用的互动入口。显示、隐藏、设置和退出继续作为独立分组。菜单操作必须在选择后立即产生可观察反馈，不能只改变不可见的内部状态。

## 4. 陪伴偏好

用户可见档位改名并提供结果说明：

- `安静`：持续轻微呼吸，较少走动和说话。
- `自然`：偶尔自己活动，适合日常使用；继续作为默认值。
- `爱玩`：更常走动和卖萌，但不会频繁弹出对白。

每个档位提供 `试试看` 操作，立即播放一组代表动作，但不修改当前生活状态或自动调度。互动气泡开关继续只控制非必要对白。

## 5. 首次配置与设置层级

首次成功路径只要求完成以下步骤：

1. 输入宠物名称。
2. 导入至少一张透明 PNG 或 WebP。
3. 第一张成功导入的图片在尚无日常照片时自动分配为 `平时陪伴`。
4. 用户可以直接保存并显示宠物。

设置界面按任务分成以下层级：

1. `宠物`：名称、当前宠物、导入照片、显示大小。
2. `行为与照片`：平时陪伴、困倦、睡觉、工作和短动作照片。
3. `陪伴方式`：陪伴档位、预览和互动气泡。
4. `提醒与休息`：提醒、声音和工作计划。
5. `高级调整`：素材归一化、脚底基线和头部热区，默认折叠或后置。

本次不增加独立的新手教学系统、账号步骤或示例提醒。高级设置保持可访问，但不得阻塞一张照片完成首次显示。

## 6. 性能、可访问性与失败行为

- 生命底噪和自主动作使用现有 CSS/Web Animations、`transform` 与 `opacity`。
- 同一时间只运行一个普通短动作；系统流程优先并可取消普通动作。
- 调度使用有限数量的短期计时器，不增加长时间高频轮询。
- 减少动态效果偏好按本设计降低动作，不应导致宠物完全失去生命反馈。
- 素材加载失败继续保留当前照片或回退到日常照片。
- 所有新增行为完全离线，不记录用户交互轨迹或增加遥测。

## 7. 产品文案

本次对所有用户可见中文文案进行一次完整审校，覆盖宠物窗口、右键菜单、托盘菜单、设置页、空状态、按钮、辅助说明、确认框、提醒、错误消息和宠物对白。不是只替换本次新增入口。

### 7.1 两种声音

产品界面和宠物对白使用两套明确声音：

- **产品声音**：平静、直接、具体。先告诉用户这是什么或会发生什么，再补充必要条件。不卖萌，不使用拟人语气，不暴露实现细节。
- **宠物声音**：短、自然、贴合眼前动作。可以有轻微性格，但不充当教练、心理咨询师或 AI 助手，不泛泛鼓励，不假装拥有用户未提供的记忆。

产品界面以可理解性优先于品牌腔调；宠物对白以场景真实感优先于句式变化。

### 7.2 写作规则

- 按钮使用能预测结果的动词，例如 `导入照片`、`保存并使用`、`稍后提醒`，避免 `确认`、`处理` 等脱离上下文的泛词。
- 标题使用用户概念。除高级调整区域外，用 `照片` 代替 `素材`，用 `桌面上的大小` 代替 `默认人物高度`，用 `调整照片` 代替 `素材归一化`。
- 辅助说明只解释当前选择最容易误解的一件事，不重复标题和按钮文字。
- 空状态同时说明现状与下一步，但不描述草稿、持久化、渲染器等实现细节。
- 错误消息采用“发生了什么 + 用户现在可以做什么”的结构；保存失败时明确原设置仍在，导入失败时明确是哪张照片及原因。
- 确认框直接说明不可逆结果，不使用夸张警告。
- 同一概念全局只使用一个名称；用户界面统一使用 `专注`，内部代码可以继续使用 `working`。
- 中文句子尽量简短，避免连续分号、括号堆叠和翻译腔。省略号只用于真实停顿或加载状态。
- 不滥用感叹号、emoji、`啦`、`呀`、`哦`、`嘿嘿`；同一对白中最多使用一种语气装饰。
- 不使用空泛句式，例如“给你一点好心情”“今天也轻轻松松”“慢慢来，做好眼前这一点”“新的清醒时间开始”。

### 7.3 宠物对白

- 单条对白优先控制在 4–12 个汉字，最多表达一个意思。
- 对白必须对应当前动作或状态：被点击时回应注意，摸头时回应触碰，困倦时表现困倦，专注时保持克制。
- 自动动作默认不说话；只有性格事件才可从小型对白池中选择一句。
- 不主动评价用户的情绪、效率、健康或工作成果，不说无法验证的安慰和承诺。
- 不模拟真人亲属的具体口头禅、共同回忆或现实身份。
- 相邻分类避免只替换少量词语的同义句，优先让动作本身承担表达。

### 7.4 术语基线

实现时按以下用户可见术语统一审校：

- `透明照片`，而不是在普通流程中反复写 `透明 PNG / WebP`；格式限制放在文件选择或辅助说明中。
- `平时陪伴照片`、`困倦照片`、`睡觉照片`、`专注照片`。
- `陪伴方式`，包含安静、自然、爱玩三档。
- `专注时段`，替代用户界面中的 `工作时段`。
- `休息提醒`、`稍后提醒`、`结束休息`。
- `调整照片`，包含大小、位置、脚底位置和摸头区域；`可见边界` 等技术信息只在高级区域显示。

不为本次审校引入完整国际化框架。重复术语可以集中为小型常量，宠物对白继续由独立对白库管理。

## 8. 验收标准

- 新用户可用一张合规图片完成宠物创建，不需要先理解动作槽、热区或归一化参数。
- 菜单中的即时动作在选择后立即开始，用户能判断操作已生效。
- 自然档普通静置时，15 秒内可观察到呼吸、眨眼或轻微点头等生命底噪。
- 自然档持续空闲约两分钟内出现至少一次明显自主小动作；普通鼠标悬停不会反复把等待时间归零。
- 工作状态保留低频生命底噪，但没有自主位移、卖萌或主动对白。
- 隐藏、休眠、提醒和休息期间正确暂停普通自主行为。
- 待机资源占用继续满足主规格的软性能预算。
- 所有用户可见中文文案均完成审校；同一概念没有混用“工作/专注”“素材/照片”等不同名称。
- 新用户只阅读界面文字即可理解主要按钮的结果，不需要知道状态机、动作槽、持久化或渲染器等实现概念。
- 宠物对白与当前动作匹配，没有泛泛鼓励、机械卖萌、假装理解用户或明显的 AI 助手口吻。

核心调度、档位范围、到期暂缓和恢复语义使用单元测试覆盖。菜单、设置层级、动作观感、首次配置、减少动态效果和文案理解度等待用户在 Windows 与 macOS 手动验证；不增加 UI 单元测试、浏览器测试或自动化端到端测试。
